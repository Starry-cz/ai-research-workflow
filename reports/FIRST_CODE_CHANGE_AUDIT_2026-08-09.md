# 首次修改论文代码审计（2026-08-09）

## 审计问题

现有仓库已经要求单变量实验、Git commit、AI 改动记录和 baseline 稳定化，但没有把“修改前冻结—改动分类—最小检查—diff 审查—AI 代码验收—回退”串成一个准入门。新手可能在一次改动中同时修环境、重构和改方法，随后无法判断结果来自研究想法、baseline 修复还是评价变化。

## 两个参考项目中可吸收的内容

### Learning Research

- 入门路线先建立知识广度，再在具体方向和真实项目中追求深度；
- 科研能力不仅是想 idea，还包括实验、写作和展示；
- 实验能力需要通过写代码、分析失败原因和实验记录持续训练；
- 原作者明确说明经验来自特定实验室与方向，需要在实践和交流中调整。

转化动作：README 保留“广度打底—深度复现—独立项目”路线；首次改码指南把一次修改设计为可解释、可验证、可回退的项目训练，而不是新的工具清单。

### AutoResearchClaw

- 把研究拆成阶段组，为关键阶段保存结构化产物；
- 提供人工参与模式、质量门控、成本预算、版本化产物和继续 / 优化 / 转向决策；
- 对实验、引用和主张增加核验机制，区分自动执行与人工判断。

转化动作：使用人工准入状态、修改前快照、风险比例检查和版本化证据链。没有吸收“一行命令生成论文”或“自动批准”的默认路径，因为自动完成阶段不等于研究结论已经验证。

## 经验材料对照

- [把 idea 变成可靠的代码的工作流](https://www.xiaohongshu.com/explore/6a1a82e400000000380345ea)强调先理解、再计划、做最小实现并验证；评论中的困难集中在 AI 改完后无法区分 idea 与实现问题。用于确认“最小 patch + 独立验证”的真实需求，不用于证明某个工具生成的代码可靠；
- [科研人员的极简 Git 实用指南](https://www.xiaohongshu.com/explore/6940d4ea000000000d00d9b9)记录科研代码与实验结果失去版本对应、忘记 commit 后无法回退的常见痛点。用于确认低门槛版本习惯，不替代 Git 官方规则；
- [计算机博士 Codex 科研入门使用心得](https://www.xiaohongshu.com/explore/6a4e055c000000001702d0c8)建议先声明目标、现有文件和预期结果，并约束 AI 不随意修改原文件。用于形成修改计划字段；其中按 Star 安装外部技能的做法未被采用，第三方代码仍需来源、许可证和内容审查；
- [科研探索目的下 Codex 老在奇怪的地方使劲](https://www.xiaohongshu.com/explore/6a76af7d000000002500743e)反映过量格式、覆盖率与边缘防御会拖慢假设验证，并建议记录假设、失败、原因和决定。用于建立按风险和主张选择检查；文中禁止门控、分支或回退的个人做法未被采用，因为数据身份、评价完整性和恢复入口仍是科研证据的一部分；
- 知乎文章[大规模编排 AI 代码审查](https://zhuanlan.zhihu.com/p/2053168414206718925)讨论根据仓库上下文和 diff 进行审查，以及生成文件也可能包含不可跳过的语义变化。用于确认逐文件审查需求，不把 AI 审查意见视为合并批准。

## 规范与项目对照

- [Google Engineering Practices](https://google.github.io/eng-practices/review/developer/small-cls.html)建议小而自包含的改动、配套测试，以及分离重构和功能修改；没有把固定行数设为本仓库硬门槛；
- [GitHub 变更审阅指南](https://docs.github.com/en/pull-requests/concepts/helping-others-review-your-changes)要求聚焦范围、说明上下文、自审 diff 并提供测试证据；个人研究仓库可以自审，不强制所有改动创建 PR；
- [GitHub AI 生成代码审阅教程](https://docs.github.com/en/copilot/tutorials/review-ai-generated-code)明确要求检查意图、测试、依赖、许可证、虚构 API，以及被删除或跳过的测试；
- [Releasing Research Code](https://github.com/paperswithcode/releasing-research-code)要求依赖、训练、评价、权重和精确命令，使代码改动能回到可运行研究入口。

## 适用边界

- 本指南适合 Git 管理的计算机与 AI 实验代码，不替代实验室的受控开发、医疗 / 安全关键软件或正式合规审查；
- 并非每次修改都需要完整训练；最低检查按改动风险与主张选择，但不能用“研究探索”作为跳过数据和评价完整性的理由；
- 测试通过只能支持被检查行为，不证明论文公式实现完全正确、方法有效、比较公平或结果可推广；
- 第二位审阅者和 PR 是推荐协作方式，不是个人项目的强制仪式；
- 自动研究系统可以提供阶段编排和产物结构参考，不能替作者核验数据、代码、实验与结论。
