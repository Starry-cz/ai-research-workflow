# 零基础首页入口审计

- 审计日期：2026-08-11
- 审计对象：`Starry-cz/ai-research-workflow`
- 问题编号：I-050
- 结论：仓库已有完整能力地图和状态分流，但行动入口位于首页约第 70 行，“30 秒选择”同时列出多类状态，真正没有科研经验的读者仍要先理解仓库术语才能决定第一步。本轮将唯一默认入口前移到目录之前，并用“对象—学习目标—产物—前置—时间—三步行动—完成标志—求助出口”约束首次体验；专项入口仍保留给已明确状态的读者。

## 1. 当前问题

根 README 原先先展示愿景、目录、适用对象和十余类问题，到约第 70 行才出现行动分流。分流本身对已有问题的读者有用，但 L0 / L1 / L2、baseline、知识复用、证据等级和投稿等多个入口会把“先做什么”的判断重新交给完全零基础读者。

准备检查表还一次展示工具、Python、机器学习、深度学习和科研工作流四类能力。虽然这些字段都有价值，但没有明确“首次只检查哪一部分”；读者可能同时打开课程、工具、模板、论文和 Agent，形成收藏增长而没有首个可验证产物。

## 2. 经验帖对照

- [计算机科研新手快速入门](https://www.xiaohongshu.com/explore/6a55f71400000000170282b1)给出“选方向—读论文—复现—映射—精读”的个人路线；评论仍集中追问怎么选方向、baseline 在哪里、前两步最难，以及把复现交给 Agent 后自己学不到什么。它证明短路线仍需要明确起点和验收，但“近两年 A 会、低 GPU、完整训练”只适合部分深度学习场景，不作为通用准入规则；
- [从零开始发论文系列（一）](https://www.xiaohongshu.com/explore/690437d00000000003020d22)的评论出现“直接按自己的想法写代码、没有 baseline、长期无进展”“要读多少篇才能选 baseline”“开源代码在哪里”等问题。它用于确认新手会跳过基线和候选比较；评论中的固定篇数、搜索方法和“都可以超过”属于个人回答，不能替代任务、代码、数据与资源门控；
- 知乎问题[计算机本科科研入门求助（文献笔记管理、AI 工具使用）](https://www.zhihu.com/question/2036962382614900853/answer/2043702641105142901)把 Zotero、Obsidian、飞书和多个 AI 工具同时放进入门决策。回答带有产品与服务推荐，本仓库只吸收“工具选择会占用起步注意力”，不采用多工具栈或商业产品结论；
- 知乎回答[本科生小白如何入门机器学习](https://www.zhihu.com/question/666314243/answer/1994435066227598413)明确提醒不要同时学习全部资源，并建议用 CPU 小任务和可展示项目起步。它包含个人课程与服务建议，本仓库只迁移“少量资源、实际产物、逐步升级”的方法。

## 3. GitHub 项目与正式教学资料对照

- [GitHub Skills Content Model](https://skills.github.com/content-model)要求课程开头说明适用对象、学习目标、产物、前置条件、时间和明确启动步骤，并删除会混淆新手的无关内容；本仓库据此建立首页起步契约，而不是复制其机器人课程结构；
- [GitHub Skills Quickstart Guide](https://skills.github.com/quickstart)建议把一个学习目标拆成三到五个递进步骤，指出第一步应容易、读者几分钟内需要看到进展，并在卡住时给出帮助入口；本仓库的完整科研路线远长于一次课程，因此只将首次实验压缩为三步，后续仍使用能力里程碑；
- [Introduction to GitHub](https://github.com/skills/introduction-to-github)用“谁适合—学什么—做出什么—前置—耗时—如何开始”组织第一天实践，并以真实仓库动作形成产物。它证明入口结构可迁移，不证明同一时长适用于科研环境配置；
- [Diátaxis Tutorials](https://diataxis.fr/tutorials/)把教程定义为在指导下，通过有意义的实际动作达到可实现目标；因此本仓库以终端运行、四项产物和解释能力验收，不以阅读完 README 验收；
- [Learning Research](https://github.com/pengsida/learning_research)把入门分为广度基础、深入一篇论文和独立项目，并强调实践与交流；其 3D Vision 和实验室条件有明确情境，本仓库只迁移阶段递进和产物导向；
- [AutoResearchClaw](https://github.com/aiming-lab/AutoResearchClaw)展示阶段、checkpoint、恢复与人工介入模式，说明复杂流程也需要明确入口和状态；自动生成完整论文的能力不作为零基础科研学习已经完成的证据。

## 4. 采取行动

- 在根 README 的目录之前增加唯一默认入口，明确适用对象、学习目标、产物、前置条件、建议时间和三步行动；
- 首次只要求核对工具能力，再进入 L0 或可运行演练；不要求同时选择真实论文、GPU、Agent 或整套课程；
- 把 `PASS`、四项运行产物、实际解释器和首个报错定义为完成 / 求助边界；
- 将指南索引中的完全零基础主线移到全部分流与资源列表之前，并加入第一次可审计实验演练；
- 在准备检查表增加 `NEEDS_L0 / READY_FOR_DRILL` 首次分流，并把首次演练不需要的 Jupyter 能力移到后续 Python 部分；
- 扩展仓库质量检查，确保默认入口持续位于目录之前，并保留时间、产物、完成标志和求助出口。

## 5. 适用边界

唯一默认入口服务于“无法判断自己处于哪一层”的读者，不取代导师任务、共享数据、服务器权限和现有实验室流程。已经拥有明确任务的人必须先确认授权；已经能展示对应产物的人可以跳过讲解。建议时间只是阅读与最小本地演练的规划窗口，不是学习能力评分，也不包含下载、安装、网络和系统故障。

首页结构通过自动检查只能证明关键入口存在、顺序稳定和链接有效，不能证明陌生读者真正理解或无提示完成。完成 I-050 后仍需要邀请未参与编写的零基础读者执行预定义任务，记录第一处犹豫、误点、求助和完成时间。
