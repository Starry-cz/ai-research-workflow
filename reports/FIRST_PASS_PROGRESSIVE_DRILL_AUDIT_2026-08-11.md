# 首次 PASS 渐进式演练审计（2026-08-11）

## 审计结论

根 README 已承诺一条唯一默认路径，但此前 L0 指南在仓库根目录创建 `.venv` 并运行调试配置后，演练页又要求进入子目录、创建第二个 `.venv`、重跑调试配置；在第一次看到 `PASS` 前，还要求阅读任务授权、数据集卡、评价协议和实验卡，并完成 baseline、candidate、多个 seed、结果主张、停止、知识检索与交接。每个部件单独正确，组合后却把“首次成功”变成了完整协议课程。

本轮将演练分为两个独立门槛：第一次只复用根目录环境、运行一个调试配置、验收四项产物；第二轮才进入两组公平比较。当前状态为 `FIRST_PASS_IMPLEMENTED / HUMAN_TIME_PENDING`。

## 规范与项目对照

- [GitHub Skills Quickstart Guide](https://skills.github.com/quickstart)建议一个课程聚焦单一能力、使用三至五个小步骤，并指出学习者若几分钟内看不到进展容易放弃；它的时间观察来自 GitHub Skills 课程，不是所有科研学习者的统一时限；
- [Diátaxis Tutorials](https://diataxis.fr/tutorials/)要求教程尽早、频繁给出可见结果，围绕“当前问题—动作—结果”推进，减少解释、选项和旁支；严格的数据、评价与结论说明应保留，但不必阻塞第一个可见结果；
- [ML for Beginners](https://github.com/microsoft/ML-For-Beginners)采用动手项目、频繁检查和由小到大的项目结构，并允许课程整体或分段学习；本仓库迁移渐进产物与分段验收，不把十二周课程设为科研前置；
- [AI for Beginners](https://github.com/microsoft/AI-For-Beginners)为完全新手单独提供快速动手示例，说明完整课程与首次可运行入口可以分层；
- [Python `venv`](https://docs.python.org/3/library/venv.html)说明虚拟环境有独立解释器且不必激活才能使用。本仓库直接调用仓库根目录 `.venv` 的解释器，避免默认路径无理由嵌套第二个环境；真实项目采用 conda、uv、Poetry 或容器时仍以项目官方环境为准。

## 发现的问题

1. L0 与演练页对同一默认路径重复创建环境和运行调试配置；
2. 第一个机器可见的 `PASS` 必须等待三组配置和完整公平比较，首页的 60–120 分钟起步承诺没有对应最小验收；
3. 首次页面先展示多个 seed、总体标准差、评价协议、停止门和知识复用，读者难以区分“现在必须做”和“以后按事件做”；
4. 常见失败仍要求确认当前目录是演练子目录，与新的根目录统一路径冲突。

## 已采取行动

- 新增 `verify_first_run.py`，复用现有产物验收逻辑，只检查单配置运行的四项文件、配置—运行 seed 一致性、完成状态、汇总重算、环境、日志和结论边界；
- 将演练页前置为“一次根目录环境—一次调试运行—一次单目录 PASS—解释四项产物”，明确可在此停止；
- 第二轮复用同一个根目录 `.venv`，只新增 baseline 与 candidate，再调用原 `verify.py` 完成公平比较；
- 修正当前目录、命令路径和失败提示；同步 L0 指南、首页、CI、贡献要求、PR 检查、变更记录与仓库自动回归；
- 保留数据集卡、评价协议、多个 seed、结果主张和知识复用材料，没有用“容易”删除科研严谨性。

## 证据边界与下一步

自动检查可以证明单运行与三组比较的两套验收逻辑一致，不能证明新手实际耗时、是否理解四项产物或是否会在第一个 `PASS` 前误入第二轮。后续真人观察应分别记录“到首次 PASS”和“到公平比较 PASS”的状态，不把只完成第一层的读者判为失败，也不把第一层证据写成方法比较结论。
