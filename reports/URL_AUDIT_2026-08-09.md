# 外部 URL 与 GitHub 项目状态审计（2026-08-09）

本报告记录一次维护快照，用于修正确定性失效和产品能力变化。它不评价资源学术质量，也不承诺链接长期可用。

## 审计范围与方法

| 项目 | 记录 |
| --- | --- |
| 检查时间 | 2026-08-09 17:52–18:00（Asia/Shanghai） |
| 自动检查范围 | `tools.yml` 中 52 个条目的 `url` 与 `web_url`，共 58 个入口 |
| 第一遍方法 | `scripts/audit_external_urls.py --timeout 15`，正常 TLS 校验、跟随重定向、仅读取一个字节 |
| 第一遍结果 | 47 个可达；11 个出现 TLS 或连接错误；没有直接返回 404 / 410 的入口 |
| 第二遍方法 | 对异常项使用系统 `curl`、GitHub CLI / API 和可访问的正式页面复核；不关闭 TLS 校验 |
| GitHub 范围 | 35 个真正的 GitHub 仓库；`github.com/features/copilot` 是产品页，不作为仓库查询 |

第一遍的 `network_error` 只代表当前客户端未能完成连接。只有第二遍仍能确认的 404、证书错误、规范重定向或产品变化才进入修改。

修正后再次审计 51 个活动条目的 56 个入口：54 个由脚本直接判定可达；Cool Papers 与 CosmosPaper 仍被该 Python TLS 栈报告证书错误，但系统 curl 在绕过代理、保持证书校验的直接连接中均返回 HTTP 200，因此保留并记录为客户端差异。

## GitHub 状态结论

- 35 个仓库在检查时均为公开且未归档；
- 仅 DVC 出现所有者更名后的规范地址变化；
- “最近更新时间”容易被 Star、Issue 等活动影响，本报告不以此判断维护质量；必要时查看 `pushedAt`、release、默认分支、README 和 Issue；
- 仓库未归档不等于文档完整、许可证适用或适合零基础，仍需执行各阶段准入检查。

## 复查方式

仓库维护者可运行：

```bash
python scripts/audit_external_urls.py --timeout 15
```

对异常项至少再用一个独立来源复核。证书错误不得使用 `--insecure` 或关闭校验后改写为“可达”；动态结果也不进入必过 CI，以免外部限流和瞬时故障阻断仓库内部质量检查。
