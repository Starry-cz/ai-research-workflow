# 已填写示例：第一次任务授权边界

> 这是仓库教学演练的权限示例，不是真实导师授权。这里的任务范围由仓库 README、脚本行为和版本控制边界共同定义。

## 1. 任务授权卡

- 任务来源与负责人：仓库维护者提供的公开教学演练；练习者对自己的本地副本负责
- 问题与交付：运行合成数据上的 baseline 与 candidate，使用 `verify.py` 核验，并说明结论边界
- 截止与验收：自定；以三组新结果目录、`PASS` 验收输出和已填写记录为准
- 允许读取：本目录的 README、Python 脚本、配置、已填写卡片和 `*-recorded` 结果
- 允许写入：本地 `results/my-*` 新目录、自己的学习笔记和个人分支
- 允许运行：本地 CPU、Python 标准库、README 中三条训练命令与验收命令
- 允许分享：公开仓库原链接、自己的非敏感日志和学习总结；不得把教学结果包装成真实科研结果
- 必须保持不变：合成数据生成逻辑、评价函数、预先声明的 seed、`*-recorded` 示例结果
- 需要确认：修改 `train.py`、`verify.py`、正式配置、已记录结果或仓库文档并准备提交上游
- 禁止：引入私有 / 个人数据、提交密钥、覆盖 `*-recorded`、编造运行、声称方法普遍更优
- 停止与升级：发现脚本与说明矛盾时保留最小复现，通过仓库支持说明选择公开 Issue 或私密渠道
- 确认依据：[演练 README](README.md)、[数据集卡](dataset-card.md)、[评价协议](evaluation-spec.md)和目录 `.gitignore`

## 2. 动作分类

### `EXECUTE_WITHIN_SCOPE`

- 创建 `.venv`；
- 运行 `debug.json`、`baseline.json` 和 `candidate.json` 到新的 `results/my-*`；
- 运行 `verify.py`；
- 阅读和比较新生成的日志、配置与指标；
- 在自己的笔记中记录结果和失败。

### `CONFIRM_BEFORE_CHANGE`

- 修改训练、数据生成或评价代码；
- 改正式配置中的 seed 集合、epoch 或除学习率外的变量；
- 覆盖或删除仓库保存的 `*-recorded`；
- 将改动提交到仓库主分支或对外声称改进成立。

### `STOP_AND_ESCALATE`

- 把真实个人、业务、受限或匿名材料加入演练；
- 上传密钥或用未获准的外部服务处理项目内容；
- 删除失败运行以隐藏与预期不一致的结果；
- 生成不存在的日志、运行或引用。
