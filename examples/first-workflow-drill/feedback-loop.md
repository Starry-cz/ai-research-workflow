# 教学演练反馈闭环示例

这是基于仓库审计问题填写的示例，不声称来自真实导师。它展示如何把一句评审问题转成可核验行动。

## FB-001：另一人真的能复查这次运行吗

- 来源 / 日期：仓库流程审计，2026-08-09
- 原始反馈：现有实验卡记录了运行和结果，但没有证明另一人能在新目录中独立复查。
- 目标对象：教学演练三组记录结果及其 `PROCEED` 决定
- 类型 / 优先级：`EVIDENCE_REQUEST` / 阻塞“可交接”主张
- 已见信息：已经看过记录结果和 `verify.py`，尚未看过空目录复跑
- 我的解释：需要从锁定 commit 导出到临时空目录，重新运行三组配置并执行自动验收；不能使用工作区生成结果
- 含义确认：由审计问题和[运行交接指南](../../docs/RUN_HANDOFF_REPLAY.md)共同固定完成标准
- 处理决定：`ACCEPT`
- 理由：现有证据只能证明维护者工作区可核验，不能支持 H2 最小复跑

### 行动与验收

- 行动：从 commit `ad6538378ff9c15a744d13ecfd9c17e1afc9de15` 导出教学目录，在 Windows 临时空目录运行 debug、baseline、candidate，再运行 `verify.py`
- 负责人：仓库维护者
- 产物：[运行交接审计](../../reports/RUN_HANDOFF_AUDIT_2026-08-09.md)与[已填写交接卡](run-handoff.md)
- 验收：临时路径检查通过；三组状态完整；`verify.py` 输出 `PASS`；指标能重算；不依赖口头修正
- 停止条件：debug 失败或超过一分钟时不启动后两组

### 验证与关闭

- 实际结果：baseline `0.840000`，candidate `0.966667`；三组加验收约 1.129 秒
- 决策更新：教学演练可标记 `H2_REPLAY / HANDOFF_READY`，但不升级为真实论文或跨平台完整训练复现
- 最终状态：`CLOSED_EVIDENCE`
- 重开条件：修改训练脚本、验收脚本、配置、记录产物或最低 Python 边界

## FB-002：候选分数更高，能否写成方法更优

- 来源 / 日期：教学场景中的主张审查，2026-08-09
- 原始反馈：candidate accuracy 高于 baseline，是否可以报告更高学习率更好？
- 目标对象：实验卡结论与候选方法表述
- 类型：`REINTERPRET`
- 我的解释：需要判断观察能支持教学协议内比较，还是能推广为方法优越性
- 处理决定：`PARTIAL`
- 理由：数值观察成立，但数据是固定合成样本，没有真实任务、独立调参协议或外部验证
- 行动：保留数值，使用[结果—主张审计](result-claim-audit.md)收缩文字，并把下一步改为筛选真实 baseline
- 验收：README、验收脚本和交接卡都明确“只证明教学证据链完整”
- 最终状态：`CLOSED_SCOPE`
- 重开条件：真实任务中预先冻结评价协议并获得独立确认性证据
