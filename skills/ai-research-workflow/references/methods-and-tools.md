# 方法与工具选择

当用户问“从哪里学”“用什么工具”“下一步做什么”或准备引入新平台时读取本页。先选方法，再决定工具；不要按 Star 或功能数量推荐。

## 选择循环

1. 写清当前阻塞、已有材料、能力等级和本轮产物。
2. 判断工具属于立即、规模增长后还是专项研究。
3. 先用现有能力完成最小试用，不迁移整个项目。
4. 检查输出能否回到代码、数据、来源、配置或日志。
5. 记录采用、暂缓或拒绝，以及重新评估的触发条件。

## 立即可用

| 问题 | 方法与最低产物 |
| --- | --- |
| 第一次使用 GitHub | 在练习仓库完成 branch、commit、Pull Request 和 merge；留下可检查历史。 |
| Python 环境不稳定 | 记录解释器、独立环境和依赖；重启内核后从头运行；留下环境文件和日志。 |
| 不理解 ML 评价 | 从小型数据、简单 baseline、固定划分和主指标开始；留下完整 Notebook。 |
| 文献越搜越乱 | 分开发现、书目、原文和管理；留下检索日志、稳定标识和主记录。 |
| 论文读不完 | 第一遍筛选、第二遍理解、第三遍只给核心论文；留下阅读层级和证据位置。 |
| 项目准备开始 | 同时规划数据、环境、评测、权限和复跑；留下 Research Brief 与运行入口。 |

推荐入口：GitHub Skills、Jupyter、scikit-learn MOOC、OpenAlex、Zotero、The Turing Way。外部信息使用前核验当前官方说明。

## 规模增长后

- **环境依赖反复冲突**：再评估 uv 等锁定方案；已有稳定项目不要无理由迁移。
- **实验数量无法手工比较**：再引入 MLflow；数据身份复杂时评估 DVC。
- **成果准备公开和引用**：完成复跑、权限与许可证决定后，再配置 CITATION.cff、release 和 Zenodo。

这些工具只管理身份、检索或归档，不自动证明实验公平、结论正确或材料可公开。

## 专项研究

- **LLM / Agent 评测**：使用 Inspect、lm-evaluation-harness 或任务自建脚本；冻结任务、prompt、模型/API、scorer、成本与重复运行。
- **RAG 诊断**：使用 RAGChecker 或等价模块化指标；分开召回、排序、上下文利用、生成和引用。

公共 benchmark 与自动 judge 只能作为评测组件。必须保留人工校准、任务适配和错误分类。

## 在仓库内查询

如果根目录存在 `knowledge-base.json`，优先运行：

```powershell
python scripts/query_knowledge_base.py --query "当前问题关键词"
```

查询结果用于选择入口，最终要求仍以当前项目材料、官方来源和实际运行证据为准。Skill 独立安装时使用本页，不假设根目录知识库存在。
