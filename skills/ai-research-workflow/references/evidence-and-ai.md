## 来源角色

为每个来源标注主要角色，不让一个入口承担全部证明责任：

- **发现**：搜索引擎、聚合页、趋势页，只生成候选。
- **书目**：DBLP、DOI、出版社页面，用于作者、标题、venue 和版本身份。
- **原文**：论文、附录、官方规范，用于核验具体表述。
- **实现**：作者仓库、release、commit、数据卡，用于复现。
- **评测**：任务定义、scorer、冻结测试集和统计协议。
- **归档**：release、DOI、长期存储和引用元数据。

## AI 使用记录

当生成式 AI 影响研究产物时，至少记录：

- 提供方、模型名、版本或调用日期；
- system prompt 或核心指令摘要；
- temperature、seed 和关键参数（若可用）；
- 输入上下文来源，以及是否含敏感或未公开信息；
- 允许调用的工具、文件、网络和执行权限；
- AI 生成的代码、检索式、标签、评语或文字如何被人工验证；
- 失败、重试、人工覆盖和最终采用范围；
- 当期 venue、机构或数据提供方的 AI 使用规则。

不要把聊天模型、聚合器或 LLM judge 作为未经复核的最终证据。

## 评测冻结

在查看最终测试结果前固定：

- 研究问题对应的主指标和辅助指标；
- 指标实现、聚合、阈值、统计单位和缺失值处理；
- 数据版本、样本单位、划分、排除规则和污染检查；
- 重复运行、随机种子、置信区间或其他不确定性方案；
- baseline/candidate 的搜索空间、预算和选择规则；
- 人工评价 rubric、盲评/抽样方式和冲突处理；
- 成功、失败、继续和停止的决策门槛。

测试后修改任何项目时，记录原因、时间和受影响主张；必要时将结果降为探索性。

## 主张证据矩阵

每个主要主张至少记录：

| 字段 | 内容 |
| --- | --- |
| 主张 | 一句话、可被反驳的表述 |
| 证据 | 论文位置、run ID、图表、代码或推导 |
| 来源角色 | 原文、实现、评测或归档 |
| 反例 | 哪些观察会推翻或削弱主张 |
| 替代解释 | 数据、实现、预算或评测造成结果的可能性 |
| 适用边界 | 数据、模型、版本、语言、场景和资源范围 |
| 核验状态 | 未核验、部分核验或已验证 |

## 表达边界

- 单次调试运行只能证明代码在该环境完成，不证明稳定性或泛化。
- 本地 baseline 与论文目标不同，不得写成“已复现论文结果”。
- 指标差异未排除随机性、搜索预算和配对错误时，只能写成初步观察。
- 有效负结果可以支持“在当前范围内未观察到收益”，不能证明方法永远无效。
- 组会、公开 artifact、预印本、同行评审与正式发表是不同成熟度，不可互相替代。
- 未确认共享权限的材料不得进入公开 Issue、仓库、外部 AI 服务或论文附件。
