# AI 科研工作流

## 核心原则

- 把研究推进定义为“产生可检查证据”，不把阅读时长、安装工具或 AI 输出当作完成。
- 先确定当前阶段与一个最小产物，再加载所需参考；不要要求用户从头阅读整套仓库。
- 分开记录事实、观察、解释、主张和待核验项；结论不得超过证据范围。
- 优先建立最简单可信 baseline 和冻结评价协议，再做改进、调参或自动化。
- 保留失败运行、负结果、停止原因和恢复入口；不要只展示最好结果。
- 未经用户授权，不推送、发布、付费、外传材料、修改共享资源、删除数据或选择许可证。

## 首轮分流

先判断用户属于哪种入口，只选择一个：

1. **尚不能稳定运行代码**：进入工具与首次实验演练。
2. **能够运行代码但没有研究问题**：形成 Research Brief，筛选 2–3 个候选方向或 baseline。
3. **已有论文或代码**：锁定来源、commit、环境、数据和官方评测，建立本地 baseline。
4. **已有 baseline，准备改进**：先冻结 Evaluation Spec，再提出一个可证伪的单变量假设。
5. **已有结果**：完成错误分类和主张—证据审计，再决定继续、修正、停止或交接。
6. **明确是 LLM、RAG、Agent 或多模态项目**：读取 [专项路线](references/research-tracks.md)，仍然遵循通用阶段。

若信息不足，最多询问三个会改变路线的问题：当前已有材料、可用数据/算力/预算、期望交付物。能从文件、日志、代码或仓库发现的事实先自行检查。

## 执行循环

每次只推进一个阶段。读取 [七阶段工作流](references/workflow-stages.md)，然后执行：

1. 确认当前阶段、已有输入、权限和资源边界。
2. 定义本轮唯一主任务：`动作 + 对象 + 范围 + 产物 + 验收 + 停止条件`。
3. 检查已有项目是否已有等价记录；优先补缺，不创建第二套台账。
4. 生成或更新最小产物，并链接原始论文、代码、配置、日志、数据或决策记录。
5. 运行与风险相称的检查；没有实际运行时明确标注“未运行”。
6. 报告完成、部分完成、阻塞和待核验项，并给出一个最小下一步。

## 参考资料路由

- **阶段、输入、产物与通过条件**：读取 [workflow-stages.md](references/workflow-stages.md)。
- **LLM / RAG / Agent / 多模态路线**：读取 [research-tracks.md](references/research-tracks.md)。
- **引用、AI 使用、评测与主张边界**：读取 [evidence-and-ai.md](references/evidence-and-ai.md)。
- **需要填写记录时**：读取 [template-routing.md](references/template-routing.md)，首次使用从 [core-templates.md](assets/core-templates.md) 复制一张轻量模板。
- **在本仓库内工作时**：可继续查询根目录 `tools.yml`、`docs/README.md`、`docs/GITHUB_RESOURCE_CATALOG.md`、`templates/` 和 `examples/first-workflow-drill/`；只读取当前任务需要的文件。
- **Skill 独立安装时**：不要假设宿主项目存在本仓库文件；使用本 Skill 自带的 references 与 assets，外部资源每一步同一角色默认不超过 3 个。
- **示例结果**：必须由实际代码或工具生成；不要手写漂亮结果冒充运行输出。

## 最低交付格式

每次交付至少包含：

- **当前阶段**：正在解决的研究问题与本轮范围。
- **本轮产物**：新增或修改的文件、记录、代码、图表或决策。
- **核验结果**：运行过的命令、测试、数据检查或来源核验；未运行项单列。
- **证据边界**：当前结果支持什么、不支持什么。
- **下一步**：一个可以独立验收的动作；阻塞时给出所需信息或负责人。

## 停止与升级

- 出现权限、隐私、未公开材料、付费、对外发布或破坏性操作时暂停并请求授权。
- baseline 尚未稳定时，不把候选改动包装成创新贡献。
- 查看测试结果后修改指标、阈值或划分时，记录变更并降级结论可信度。
- 同一阻塞重复出现时，保存命令、首个关键报错、已排除原因和最小复现，再求助或交接。
- 涉及投稿规则、会议政策、价格、API、模型版本或许可证时，使用当期官方来源核验。
