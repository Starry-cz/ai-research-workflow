# 导师与组会反馈闭环

这份指南用于把导师、同伴或代码审阅中的一句建议，转换成可确认、可执行、可验证和可关闭的研究动作。目标不是证明“听从了导师”，而是避免建议在口头、PPT 和下周任务之间失真。

## 什么时候启用

- 组会或一对一讨论改变了研究问题、baseline、数据、评价或主张；
- 导师要求补实验、重做图表、解释异常或收缩结论；
- 多位导师 / 合作者给出冲突建议；
- 同一建议连续几周出现，却没有对应证据或关闭条件；
- AI、审稿人或同伴提出了会影响关键判断的修改意见。

普通措辞和排版建议可以直接进入任务卡。会改变证据链、资源预算、协议或里程碑的反馈才需要完整闭环；已有实验室 Issue 或项目系统时复用现有记录。

## 反馈不是行动，更不是结论

一条反馈至少经过以下链路：

```text
原始反馈 → 目标与类型 → 你的解释 → 对方确认
        → 处理决定 → 原子行动 → 新证据 → 再验收 → 关闭或重开
```

只写“导师建议再做一个实验”仍然无法执行。需要明确它想排除哪个替代解释、需要哪组对照、会影响哪项主张，以及什么结果算回答了问题。

## 第一步：忠实捕获并确认含义

每条关键反馈记录：

- `feedback_id`、日期、来源和会议 / 文档位置；
- 原始表述或不改变含义的短摘要；
- 指向的主张、run、图表、代码、数据或里程碑；
- 你的解释：“我理解需要验证的是……，完成信号是……”；
- 对方是否确认；未确认时不得假装已经理解。

录音、聊天截图或逐字稿不是默认要求，涉及隐私和团队政策时先取得同意。关键是保留语义、目标和确认，不是无限记录人际细节。

## 第二步：分类并判断优先级

| 类型 | 要回答的问题 |
| --- | --- |
| `CLARIFY` | 哪个定义、假设、图或表达没有说清？ |
| `EVIDENCE_REQUEST` | 缺哪项对照、复算、消融、切片或来源？ |
| `CORRECTION` | 哪个事实、实现、数据或评价可能错误？ |
| `PROTOCOL_CHANGE` | 是否要改变 split、指标、baseline、预算或实验流程？ |
| `REINTERPRET` | 现有结果是否只能支持更弱或不同的主张？ |
| `PRIORITIZE` | 在资源约束下先做什么、暂停什么、退出条件是什么？ |
| `EDITORIAL` | 只改变呈现，不改变证据或研究判断？ |

优先处理诚信、安全、数据 / 评价错误和会阻塞当前门控的问题。导师觉得“有意思”不自动代表高优先级；用当前研究问题、证据缺口、资源和截止条件排序。

## 第三步：只作一个处理决定

| 决定 | 使用条件 |
| --- | --- |
| `ACCEPT` | 反馈目标明确、与当前目标一致，且有合理证据或风险依据。 |
| `PARTIAL` | 接受核心问题，但需要缩小范围、改变实现或分阶段验证。 |
| `DECLINE_WITH_EVIDENCE` | 与已确认事实、权限、资源或研究边界冲突；记录依据并与决定者沟通。 |
| `DEFER_WITH_TRIGGER` | 当前不做，但写明重新触发的日期、证据、资源或里程碑。 |
| `NEEDS_CLARIFICATION` | 无法判断对方要求、对象或完成标准，先确认而不盲目执行。 |
| `CONFLICT_REVIEW` | 多方意见冲突或会改变已冻结协议，交给明确的决策负责人处理。 |

尊重导师不等于静默照做，也不等于用“独立思考”忽略建议。对关键分歧，展示原证据、可选方案及代价，请负责最终研究判断的人确认。

## 第四步：转换成原子行动

每项已接受反馈必须写成：

```text
动作 + 对象 + 范围 + 负责人 + 产物路径
     + 验收方法 + 截止 / 复查日 + 停止条件
```

示例：

```text
在不改变训练配置的前提下，由小王在周四前对 run-021 与 run-024
重算三个预先定义的数据切片；保存脚本、逐样本输入和结果表。
三个切片均可由评价脚本复算且差异解释已更新，才算回答该反馈。
```

“补实验”“看看数据”“继续优化”不是行动项。一个行动只设一个负责人；协作者可以参与，但不能用“大家”掩盖责任。

## 第五步：用证据关闭，而不是用完成感关闭

完成代码、跑出新数字或做完 PPT 都不是自动关闭。验收人要检查：

1. 原反馈的问题是否被回答，而不只是执行了相似动作；
2. 新证据能否回到 commit、config、run ID、脚本和结果；
3. 是否引入新混杂、协议变化、测试后选择或主张越界；
4. 研究决定、周会入口和下一步是否同步更新；
5. 什么新事实会使该反馈重新打开。

最终状态只选一种：

| 状态 | 含义 |
| --- | --- |
| `CLOSED_EVIDENCE` | 已按预设验收取得证据并更新决定。 |
| `CLOSED_SCOPE` | 通过收缩主张或明确非目标关闭，未伪装成实验支持。 |
| `DEFERRED_TRIGGER` | 触发条件和负责人明确，当前不占用活动任务。 |
| `DECLINED_EVIDENCE` | 已与决定者沟通，并记录不采纳的事实或边界依据。 |
| `OPEN_BLOCKED` | 已接受但受权限、资源或前置任务阻塞。 |
| `NEEDS_CLARIFICATION` | 语义或完成条件仍不明确。 |

## 结果出现后改变协议

导师反馈也不能抹掉时间顺序。看到测试结果后提出的新指标、切片、阈值或样本排除属于事后分析；可以探索，但必须：

- 保存原评价协议和原结果；
- 标记建议出现的时间和已见信息；
- 将新分析标为探索性，或在独立数据 / 新运行中确认；
- 不把反馈者身份当作预注册或独立验证的替代。

涉及数据、评价或 baseline 的建议应返回相应门控，不得直接在最终表格中静默修改。

## 多方反馈冲突

不要把相反建议平均成一个折中方案。先比较：各方假设的目标、受众、证据、资源和决策权限是否相同。然后形成两到三个明确选项，列出各自代价、可逆性和最小验证，由项目负责人决定。未解决前使用 `CONFLICT_REVIEW`，不要让不同成员并行执行互相抵消的改动。

## 最小记录块

可以把以下字段放入[每周复盘](../templates/05-weekly-review.md)、Issue 或实验室现有系统：

```text
feedback_id / 来源 / 日期 / 原始表述
目标对象 / 类型 / 优先级 / 已见信息
我的解释 / 对方确认
处理决定 / 理由与证据
行动 / 负责人 / 截止 / 产物 / 验收
验证结果 / 决策更新 / 最终状态 / 重开条件
```

## AI 辅助边界

AI 可以整理会议笔记、聚类重复反馈、检查行动项是否缺负责人和验收、关联代码 diff 与 run ID。AI 不能替导师确认一句模糊建议的真实含义，不能伪造“已沟通”，也不能仅凭措辞强弱决定优先级。使用 Supervisor-Skills 或其他“AI 导师”时，其输出仍属于待审建议；关键研究判断需要回到数据、论文、代码、真实导师或有责任的合作者。

## 最低验收清单

- [ ] 每条关键反馈有稳定 ID、来源、目标和时间；
- [ ] 原始语义与自己的解释分开，歧义已经确认；
- [ ] 已选择一个处理决定并记录理由；
- [ ] 接受项有单一负责人、产物、验收、截止和停止条件；
- [ ] 反馈引起的协议变化保留原版本并标记事后性；
- [ ] 新证据能够回到运行、代码、数据或文献；
- [ ] 状态按证据关闭，并同步研究决定与下一步；
- [ ] 延期、拒绝与冲突都有触发或升级路径，不在周报中长期悬空。

## 依据与延伸阅读

- [Learning Research](https://github.com/pengsida/learning_research)：通过每周 meet 展示、实验记录和失败分析训练科研能力；其经验来自特定 3D Vision 实验室，不是统一培养制度；
- [Supervisor-Skills](https://github.com/HKUSTDial/Supervisor-Skills)：把资深科研经验结构化为指南和 AI skills；项目仍处早期且侧重作者专长，AI 建议不能替代真实监督和证据审核；
- [Building and sustaining mentor interactions as a mentee](https://pmc.ncbi.nlm.nih.gov/articles/PMC8490489/)：共同确认目标、会议方式、议程、反馈开放程度和下一步；
- [The Science of Effective Mentorship in STEMM](https://www.ncbi.nlm.nih.gov/books/NBK552762/)：书面目标与行动计划需要定期检查，工具本身不能保证落实；
- [Ten Simple Rules for Getting Involved in Your Scientific Community](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1002232)：具体行动、单一负责人和截止时间；
- [GitHub Issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues)：用 assignee 明确负责人，并把分支 / PR 与问题关联到关闭证据。
