# 第一个机器学习训练—验证—测试闭环

这份指南连接“会运行 Python”和“开始读论文代码”。它不要求先掌握全部数学推导，而是要求你能用仓库内已经运行过的例子解释一条完整、无明显泄漏的机器学习链路。

完成后，你应该能不看定义回答：

```text
一个样本由什么组成？
模型读取什么并输出什么？
loss 为什么能推动参数更新？
训练集、验证集和测试集分别允许做什么？
一个指标来自哪个数据、配置和 run_id？
什么现象可能是过拟合、泄漏或评价不匹配？
```

## 1. 用一个二分类例子建立词汇映射

本仓库的[教学脚本](../examples/first-workflow-drill/train.py)使用固定合成数据训练一个极小的逻辑回归模型。它不是论文模型，但包含最小机器学习闭环：

| 概念 | 本例中的具体对象 |
| --- | --- |
| 样本、特征与标签 | 每行是 `(x1, x2, label)`；两个数值特征用于预测二分类标签。 |
| 模型与参数 | 三个可学习权重把特征映射为一个概率。 |
| 前向计算 | 线性组合经过 sigmoid 得到属于正类的概率。 |
| loss | 二元交叉熵衡量预测概率与标签的差异，用于计算更新方向。 |
| 优化 | 梯度下降根据训练集的平均梯度更新权重。 |
| epoch | 完整遍历一次训练集；本例没有 mini-batch，只为降低代码复杂度。 |
| 指标 | accuracy 便于理解结果，loss 保留概率误差信息；两者回答的问题不同。 |
| seed | 只控制权重初始化；本例用多个预先声明的 seed 描述初始化波动。 |

先打开脚本，依次找到 `build_dataset`、`train_once`、`evaluate` 和 `summarize`。如果只能运行、不能指出这些函数各自读写什么，就还没有完成本节。

## 2. 三类数据的权限不同

```text
训练集：学习模型参数和只从训练数据估计的预处理参数
验证集：选择超参数、checkpoint、阈值和方案
测试集：在方案与选择规则冻结后，评价最终结果
```

| 数据角色 | 可以做什么，不能做什么 |
| --- | --- |
| **训练集** | 用于 `fit`、梯度更新和拟合归一化、词表或特征选择；不能用训练分数代替泛化能力。 |
| **验证集** | 用于调参、早停和方案选择；反复根据它修改方法会逐渐对验证集过拟合。 |
| **测试集** | 用于冻结方案后的最终评价；不能根据测试分数选择 seed、学习率、模型或预处理。 |

不存在通用的 6:2:2、8:1:1 或其他固定比例。划分应考虑样本量、类别、组别、主体、时间、重复测量和目标部署场景。来自同一人、视频、病人、设备或时间窗口的高度相关样本，不能只随机打散后分到不同集合；时间预测通常要按时间顺序切分。

## 3. 训练循环到底做了什么

把任何深度学习训练代码先压缩成下面的逻辑：

```text
冻结数据划分、预处理与配置
  → 初始化模型参数
  → 读取一批训练样本
  → 前向计算预测与 loss
  → 清空旧梯度并反向传播
  → 优化器更新参数
  → 重复直到达到 epoch 或停止条件
  → 在验证集选择方案
  → 冻结后在测试集评价
  → 保存配置、日志、权重和指标
```

本例手写梯度，没有 PyTorch 的 `loss.backward()` 和 `optimizer.step()`，但角色完全对应。迁移到框架代码时，应能指出：数据来自哪个 loader、模型输出的 shape、loss 输入、梯度清零、参数更新、训练 / 推理模式切换，以及指标在哪个 split 上计算。

## 4. loss、指标和“效果好”不是同一件事

- **loss** 服务于训练目标；它是否下降只能说明优化过程发生变化，不能单独证明任务价值；
- **指标** 应对应研究问题，例如类别不平衡时 accuracy 可能掩盖少数类失败；
- **训练指标好、验证指标差** 常见于过拟合，但也可能来自划分偏移、预处理不一致或标签问题；
- **验证与测试都高** 仍需检查泄漏、重复样本、评价脚本和简单基线；
- **指标提高** 还要比较计算成本、波动、失败案例和适用范围。

在真实项目中，先用一句话写出指标为什么能回答任务目标，再确定主指标与辅助指标；不要因为代码默认输出某个数字就把它当成论文主结果。

## 5. 最小泄漏检查

数据泄漏是本不应在训练或选择阶段出现的信息进入了模型、预处理或决策过程，常导致过于乐观的结果。运行前至少检查：

- [ ] 先固定划分，再拟合归一化、缺失值填充、特征选择、词表或数据增强统计；
- [ ] 同一实体、重复样本或其近似副本没有跨集合出现；
- [ ] 标签或未来时刻信息没有藏在文件名、路径、时间字段或特征中；
- [ ] 验证集用于选择，测试集没有参与调参、seed 选择或 checkpoint 选择；
- [ ] baseline 与候选方法使用相同划分和评价脚本；
- [ ] 数据划分脚本、随机规则、样本 ID 或校验值可以复查。

“删除测试标签再训练”并不自动避免泄漏。只要预处理统计、重复样本或未来信息进入训练，测试结果仍可能失真。

## 6. 用仓库演练做一次口头复盘

先完成[第一次可审计实验演练](../examples/first-workflow-drill/README.md)，再打开已保存结果：

1. 在 `train.py` 中说明 180 条样本如何固定生成并切成 120 / 30 / 30；
2. 说明只有 `train_rows` 参与梯度更新，`evaluate` 不更新权重；
3. 对照 baseline 和 candidate 配置，确认正式比较只改变学习率；
4. 说明两份配置在运行前已经写定，本例没有看到测试结果后继续搜索第三个学习率；
5. 从 `metrics.json` 找到全部 seed、均值、波动与结论边界；
6. 解释为什么 candidate 数值更高仍不能证明一种普遍的新方法。

本例为教学方便对两份预先冻结的最终配置都保存了测试结果。真实调参阶段应先在训练 / 验证数据上完成选择，再按预定协议使用测试集；看完测试结果后新增方案，应当视为新的研究轮次并披露测试集已被使用。

## 7. 四个由浅到深的练习

### 练习 A：只解释，不改代码

画出 `data → model → probability → loss → gradient → weights → metric`，标出每一步的输入、输出和数据 split。无法解释的地方写成问题，不让 AI 直接替你填答案。

### 练习 B：做一次单变量运行

复制一份配置，只修改 `epochs` 或 `learning_rate` 中的一项，使用新 `experiment_id` 和输出目录运行。运行前写出预测；运行后比较全部计划 seed，不只看最高 accuracy。

### 练习 C：发现一个故意的泄漏方案

回答为什么“先用全部数据计算归一化均值，再切训练与测试”不可靠，以及正确顺序是什么。只做推理，不需要污染现有脚本和结果。

### 练习 D：迁移到 PyTorch 官方教程

完成 [PyTorch Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html)中的数据、模型、自动微分、优化与保存部分。为一个 batch 记录：

```text
features shape / dtype / device
labels shape / dtype / device
model output shape
loss 标量
一个参数的 gradient 是否存在
训练前后 loss 的变化
```

官方教程使用训练与测试数据演示 API；进入科研项目时仍要根据任务增加独立验证协议，不能把教程的数据组织直接当成所有论文的标准。
