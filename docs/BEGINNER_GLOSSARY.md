# 零基础默认路径术语速查

这不是需要背诵的“科研黑话大全”，只解释本仓库默认路径中会直接影响下一步操作的词。第一次遇到陌生词时，只读对应条目，然后回到原命令或文件；不要为了“先把术语学完”暂停整个练习。

每个条目回答三个问题：

- `通俗含义`：在本仓库当前上下文中指什么；
- `现在要做什么`：读者需要执行或检查的最小动作；
- `不能推出什么`：防止把一个词误当成更强的证据。

同一个词在不同领域可能有不同含义。本页优先采用 GitHub、Git、Python、PyTorch、scikit-learn 和 MLflow 等原始文档，并写明本仓库中的操作性用法；导师、团队、论文和目标会议另有定义时，以对应原始说明为准。

## 先看懂路线与状态

### L0、L1、L2、L3

- **通俗含义**：本仓库用来选择起点的四个操作等级，依次表示工具链、AI 基础、论文复现和研究实践的建议入口。
- **现在要做什么**：只选择与当前可展示产物一致的入口；不会判断时从 L0 检查表开始。
- **不能推出什么**：它不是学历、智力、科研潜力或论文质量评价，也不是通行的行业等级。

### PASS

- **通俗含义**：当前验收脚本列出的规则全部通过。
- **现在要做什么**：阅读 PASS 后面的范围说明，并能指出对应文件和命令。
- **不能推出什么**：PASS 不等于论文复现成功、方法更优、数据真实、结果可发表或所有电脑都能运行。

### 产物与证据

- **通俗含义**：产物是运行或研究留下的文件、记录、图表和模型；证据是能支持某个具体判断且可回到来源的产物。
- **现在要做什么**：保存配置、环境、日志和指标，并记录由哪条命令生成。
- **不能推出什么**：文件存在不等于内容正确；截图、口头描述或 AI 总结也不能自动替代原始记录。

## Git 与 GitHub

### 仓库（repository / repo）

- **通俗含义**：包含项目文件和 Git 历史的目录；GitHub 上的是远程仓库，clone 后电脑上会有本地仓库。
- **现在要做什么**：用 `git rev-parse --show-toplevel` 确认自己位于哪个仓库。
- **不能推出什么**：能查看或 clone 公共仓库不等于拥有修改远程仓库的权限。

### clone

- **通俗含义**：把远程仓库及其历史复制到本机，并保留远程连接信息。
- **现在要做什么**：使用仓库页面提供的 URL clone，再进入新目录。
- **不能推出什么**：clone 不是 fork，也不会获得远程写权限。

### 本地与远程（local / remote）

- **通俗含义**：本地是当前电脑上的仓库；远程是 Git 记录的另一个仓库地址，通常位于 GitHub。
- **现在要做什么**：运行 `git remote -v` 查看远程名称、读取地址和推送地址。
- **不能推出什么**：本地成功不代表远程已更新；远程地址存在也不代表当前账号有权限写入。

### origin 与 upstream

- **通俗含义**：`origin` 通常是 clone 时自动创建的默认远程名称；`upstream` 常被用来表示 fork 所对应的原项目，但名称只是约定。
- **现在要做什么**：始终用 `git remote -v` 看实际 URL，不根据名字猜所有者。
- **不能推出什么**：`origin` 不一定属于你，`upstream` 也不会被 Git 自动赋予特殊权限。

### 分支（branch）

- **通俗含义**：同一仓库历史中的一条工作线，允许在不直接改变默认分支的情况下练习或开发。
- **现在要做什么**：首次练习创建 `learning/first-run`，并用 `git branch --show-current` 核对。
- **不能推出什么**：创建本地分支不会自动在 GitHub 创建同名分支。

### 工作区、暂存区与 status

- **通俗含义**：工作区是正在编辑的文件；暂存区是准备进入下一次 commit 的改动集合；`git status` 显示它们的当前状态。
- **现在要做什么**：先运行 `git status --short`，只暂存自己检查过的路径。
- **不能推出什么**：文件出现在工作区不代表已经暂存，暂存也不代表已经 commit 或发布。

### diff

- **通俗含义**：显示文件内容之间的差异；`git diff --cached` 专门显示已暂存、即将提交的差异。
- **现在要做什么**：commit 前阅读 `git diff --cached`，确认没有密钥、数据或无关文件。
- **不能推出什么**：diff 为空只说明当前比较范围没有内容，不证明整个项目未发生变化。

### commit

- **通俗含义**：把暂存区内容记录为一个可定位的本地版本，带有作者、时间、说明和唯一标识。
- **现在要做什么**：精确暂存后 commit，再用 `git log -1 --oneline` 找到它。
- **不能推出什么**：commit 不等于 push，不会自动公开，也不表示代码或实验已经正确。

### push

- **通俗含义**：把本地分支的 commit 发送到某个远程仓库。
- **现在要做什么**：只有在确认远程所有者、写权限、目标分支和公开边界后才执行。
- **不能推出什么**：能 clone、能本地 commit 或已经登录 GitHub，都不保证能够 push。

### fork 与 Pull Request（PR）

- **通俗含义**：fork 是位于自己账号下、与原项目保持关系的独立仓库；Pull Request 是请求项目维护者审阅并合并一组改动。
- **现在要做什么**：向没有写权限的公开项目贡献时，先 fork，在自己的分支提交和推送，再发起 PR。
- **不能推出什么**：PR 不是直接写入上游，也不保证被接受；fork 公开仓库时，个人副本通常也公开。

## Python 环境

### Python 解释器

- **通俗含义**：真正读取并执行 `.py` 文件的程序；一台电脑可能同时存在多个解释器。
- **现在要做什么**：打印 `sys.executable`，确认路径指向当前项目的 `.venv`。
- **不能推出什么**：终端能运行 `python` 不等于 IDE、Notebook 和 `pip` 正在使用同一个解释器。

### 包、依赖与 pip

- **通俗含义**：包是可安装的 Python 代码；依赖是当前项目运行所需的包；`pip` 是常用的包安装工具。
- **现在要做什么**：使用目标解释器执行 `python -m pip`，并只安装项目官方说明要求的依赖。
- **不能推出什么**：安装成功不代表版本、CUDA、系统库或运行入口与项目兼容。

### 虚拟环境与 `.venv`

- **通俗含义**：虚拟环境为一个项目保存独立的解释器入口和包集合；`.venv` 是本仓库采用的目录名。
- **现在要做什么**：在仓库根目录创建一次，并直接调用其中的解释器。
- **不能推出什么**：`.venv` 不是唯一环境工具；真实论文项目指定 conda、uv、Poetry 或容器时，应遵守其官方方案。

## 一次实验运行

### 配置与配置快照（config / config snapshot）

- **通俗含义**：配置是运行前选择的参数；配置快照是脚本实际读取并随本次运行保存的那一份设置。
- **现在要做什么**：打开 `config.snapshot.json`，核对它与命令、日志和指标属于同一运行目录。
- **不能推出什么**：原始配置文件没有变化，不代表运行时没有覆盖参数或读取其他默认值。

### 运行与 `run_id`

- **通俗含义**：运行（run）是代码的一次执行；`run_id` 是区分不同运行的标识，本演练用独立目录名承担这个角色。
- **现在要做什么**：每次使用新目录，并让配置、环境、日志和指标都能回到同一 `run_id`。
- **不能推出什么**：重复使用同一个名字不能证明两次运行相同，覆盖旧目录还会破坏追踪。

### 日志（log）

- **通俗含义**：按运行过程记录命令、进度、警告、错误和状态的文本。
- **现在要做什么**：失败时保留完整命令、首个错误和 `run.log`，先找最早出现的原因。
- **不能推出什么**：日志最后一行正常或终端没有红字，不代表所有计划步骤都完成。

### 指标（metric）

- **通俗含义**：按明确规则把表现转换成数值，例如本演练的 accuracy 和 loss。
- **现在要做什么**：同时记录指标名称、实现、数据范围、聚合方式和方向。
- **不能推出什么**：指标更高不一定更好；单个平均值也不能说明稳定性、公平性或实际价值。

### 随机种子（seed）

- **通俗含义**：某些伪随机过程的起始值；相同代码和条件下，它可帮助重复同一随机路径。
- **现在要做什么**：调试时先用一个 seed；正式比较时预先声明两组共同使用的 seed 集合，并保留全部结果。
- **不能推出什么**：固定 seed 不保证跨硬件、库版本和并行算法完全确定，也不能代替多次运行与不确定性分析。

### 调试运行（debug run）

- **通俗含义**：用很小数据或很少训练轮数检查参数读取、训练、评价和写文件能否连通的低成本运行。
- **现在要做什么**：先让调试运行生成四项产物并通过单目录验收。
- **不能推出什么**：调试运行通过不等于训练收敛、baseline 复现或候选方法有效。

### 基线与候选（baseline / candidate）

- **通俗含义**：baseline 是与研究主张相匹配的比较参照；candidate 是准备与它公平比较的新设置或方法。本演练中，两者是只改变一个主要变量的两份配置。
- **现在要做什么**：先稳定 baseline，记录来源、版本和本地结果，再给两者相同的数据、评价规则和合理调参机会。
- **不能推出什么**：baseline 不总是“最简单模型”或“最新 SOTA”；候选一次分数更高也不能证明方法普遍更优。

### epoch 与 loss

- **通俗含义**：epoch 通常表示训练数据被完整迭代一次；loss 是训练过程希望降低的误差函数值。
- **现在要做什么**：在同一次比较中记录训练轮数和 loss 定义，并结合目标指标判断。
- **不能推出什么**：loss 更低不必然意味着目标指标更好；不同实现、数据和归一化方式下的 loss 数值不能直接横向比较。

### checkpoint

- **通俗含义**：训练过程中保存的模型状态，常用于恢复、评估或继续训练。
- **现在要做什么**：真实项目中记录生成它的 commit、配置、数据和选择规则。
- **不能推出什么**：有 checkpoint 不代表来源可信、许可允许、结构兼容或结果可复现。

### CI 与 GitHub Actions

- **通俗含义**：持续集成（Continuous Integration，CI）是在提交或 PR 上自动运行检查；GitHub Actions 是本仓库使用的托管执行平台。
- **现在要做什么**：查看具体 job、操作系统、Python 版本和实际运行命令，而不只看一个绿色标记。
- **不能推出什么**：CI 通过只覆盖对应提交和 runner 环境，不代表个人 IDE、GPU、服务器、网络与真实论文依赖均通过。
