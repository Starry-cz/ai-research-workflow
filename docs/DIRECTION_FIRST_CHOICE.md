# 零基础 AI 科研方向选择：先选可执行问题

方向选择的第一目标不是预测下一个热点，而是找到一个与你的指导条件、数据、能力和资源匹配，能够完成第一次可信闭环的问题。CV、NLP、多模态、推荐和图学习只是领域标签；真正执行时必须落到输入、输出、数据、baseline、指标和失败条件。

## 先判断你的起点

```text
有导师或项目的明确任务？
├─ 是 → 先确认交付、数据权限、baseline、时间和可自主调整范围
└─ 否
   ├─ 有真实问题或合法数据？
   │  └─ 从决策需求、样本单位、标签和评价代价定义任务
   └─ 只有宽泛兴趣？
      └─ 对 2–3 个候选做低成本扫描，只选择资料完整且资源可承受的一项
```

不要跳过导师或团队约束。已有项目时，先按[第一项导师任务授权边界](FIRST_MENTOR_TASK_BOUNDARY.md)问清自己负责的是复现、数据、实验、分析还是写作，并区分可直接执行、需要确认和必须升级的动作；不要在没有授权的情况下改变数据、目标或对外承诺。

## 把领域名改写成任务句

宽泛方向不能直接进入检索。使用下面的句式：

```text
在【目标场景】中，给定【输入与样本单位】，预测 / 生成 / 检索【输出】，
主要困难是【可观察失败】，使用【主指标与代价】评价，
当前准备从【可核验 baseline】开始。
```

示例：

```text
不是：我想做多模态。
而是：在公开图文检索数据上，给定一条文本查询，从候选图片中检索匹配项；
当前关注低频概念上的召回失败，以官方 Recall@K 协议评价，从作者提供的预训练 baseline 开始。
```

示例只展示问题粒度，不推荐特定研究方向，也不证明该问题具有论文新颖性。

## 六项匹配检查

| 检查维度 | 需要回答的问题 |
| --- | --- |
| **指导** | 谁能对领域定义、数据、实验和结论提供反馈？多久能获得一次有效反馈？ |
| **数据** | 来源、许可证、隐私、样本单位、标签和划分是否可核验？ |
| **baseline** | 是否有论文正式版本、作者代码、训练 / 评测入口、权重和近期可用记录？ |
| **资源** | 下载、存储、显存、运行时间、费用和等待时间是否可承受？ |
| **能力** | 当前缺口能否通过一个小练习补齐，还是需要先学习整套系统或领域知识？ |
| **兴趣** | 你愿意持续分析哪类失败，而不只是喜欢模型名称或宣传演示？ |

任何一项出现硬阻塞，都先缩小范围、寻找替代数据或切换候选，不用热度说服自己忽略风险。

## 三类常见起点

### A. 导师或团队给出方向

先形成一页任务合同：

- 预期交付和截止条件；
- 当前最可信的论文、代码和数据入口；
- 自己负责与不负责的范围；
- 允许修改的变量、需要提前审批的决策；
- 周会前应留下的证据；
- 如果任务不可行，何时、带什么证据提出转向。

同时写明允许读取、写入、运行、分享和付费的范围，以及对应决定负责人。导师给出领域名不等于问题已经定义，也不等于已授权修改共享状态；把模糊要求改写成任务句，并请对方确认。

### B. 已有真实问题或数据

先做数据与决策审计，不要先套模型：

- 谁会使用结果，错误的真实代价是什么？
- 样本、主体、时间和标签如何产生？
- 数据是否代表目标场景，哪些群体或条件缺失？
- 训练、验证和测试应按什么单位隔离？
- 一个简单统计规则或传统模型能否成为更合适的首个 baseline？

数据能下载不等于可以使用，也不等于该问题适合机器学习。

### C. 只有宽泛兴趣

保留两个到三个候选，每个只做低成本扫描：

1. 写出一条任务句和一条非目标；
2. 找一篇问题定义或综述、一篇成熟 baseline、一篇近期工作；
3. 找到数据、作者仓库、预训练评测或最小 demo；
4. 估算最小运行的设备、存储、时间和费用；
5. 写出最可能失败的环节和停止条件；
6. 用[首篇 baseline 准入卡](../templates/11-first-baseline-gate.md)比较后只选一项。

扫描的目标是排除不适合当前阶段的候选，不是在没有实践前证明自己将长期热爱某个方向。

## 不用热门方向列表做决定

热门方向列表可以帮助发现术语，但不能回答：

- 你是否有合法数据和可运行 baseline；
- 你的硬件能否完成最小验证；
- 谁能审查领域假设和评价协议；
- 该方向当前最关键的失败是什么；
- 你能否在有限时间内留下可信产物。

选择时优先任务成熟度和反馈条件，再考虑论文数量、社区活跃度和个人兴趣。不要只因方向“新”而选择，也不要只因方向成熟就声称没有研究空间。

## 方向试运行

选择候选后，先做一次可退出的试运行：

```text
固定任务句与非目标
  → 核验三篇代表论文与作者仓库
  → 运行预训练评测或最小 demo
  → 记录一个真实失败或差异
  → 评估能力、资源和反馈条件
  → PROCEED / REFINE / PIVOT / STOP
```

- **PROCEED**：最小链路通过，问题仍值得投入，进入正式复现；
- **REFINE**：问题可行但范围过大，缩小数据、模型或主张；
- **PIVOT**：实际观察支持另一个任务或候选，保留原证据后转向；
- **STOP**：数据、权限、资源、指导或 baseline 存在不可接受风险。

方向转变不是失败。无记录地频繁追热点才会让投入无法积累。

## 向导师或同伴提出可回答的问题

不要只问“哪个方向好”。带着以下材料沟通：

```text
我的起点：导师任务 / 真实问题或数据 / 宽泛兴趣
两个候选任务句：
每个候选的代表论文、数据、baseline 与资源：
已完成的最小运行：
最关键风险：
我倾向的选择及理由：
希望对方判断的一个具体问题：
```

AI 可以帮助生成候选关键词、整理比较维度和检查遗漏，但不能代替导师可用性、数据授权、真实运行和个人长期投入的判断。

## 通过条件

进入 M4 后继续投入前，至少能够展示：

- 一条明确的任务句和非目标；
- 两到三个候选的低成本比较；
- 一个通过准入或仍有明确核验计划的 baseline；
- 数据、资源、能力和指导条件；
- 第一个运行命令、成功标准、停止条件和备选候选。
- 当前任务处于 `READY_WITHIN_SCOPE`，或待确认 / 权限 / 升级项已经指定负责人且没有被静默越过。

对应记录使用[研究简报](../templates/01-research-brief.md)与[首篇 baseline 准入卡](../templates/11-first-baseline-gate.md)。
