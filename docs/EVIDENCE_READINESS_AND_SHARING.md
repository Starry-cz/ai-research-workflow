# 实验结果证据等级与表达边界

这份指南用于实验刚出结果、准备组会汇报、发给合作者、公开仓库或写论文时，判断“现在到底能说到哪一步”。它不替代[结果—主张审计](RESULT_TO_CLAIM.md)：后者审查一条主张是否被证据支持，本页先判断当前证据成熟到什么程度，以及谁被允许看到对应材料。

```text
验证成熟度 V0–V4 ──回答── 结果经受了什么检查
共享权限 S0–S3   ──回答── 谁被允许看到哪些材料
主张审计          ──回答── 具体一句话能否成立
```

> 能汇报不等于能公开，能公开不等于能复用，artifact 可运行不等于科研主张成立，写进论文也不等于结论已经被独立复现。

## 1. 先确定本次输出

每次判断只针对一个明确输出，不给“整个项目”笼统评级：

- 一条调试消息、一个指标或一张临时图；
- 一页组会幻灯片或一项项目决定；
- 发给合作者的结果包；
- 公开仓库、技术报告、博客或演示；
- 论文中的一张表、一幅图或一条 `claim_id`。

同一项目中，不同结果可以处于不同等级。新实验不能继承旧实验的等级；改了数据、评价、代码、选择规则或主张范围后必须重判。

## 2. 验证成熟度 V0–V4

| 等级 | 当前证据 | 可以做什么 | 不能据此做什么 |
| --- | --- | --- | --- |
| **V0 `UNVERIFIED_SIGNAL`** | 截图、单条日志、单次运行或手抄数字；身份、协议或完整性尚未确认。 | 定位错误、形成下一条检查。 | 比较方法、汇报“已经提升”、公开排行榜或写论文结论。 |
| **V1 `TRACEABLE_OBSERVATION`** | 能回到 commit、config、命令、`run_id` 和原始输出；但仍是 debug、pilot、不完整运行或事后探索。 | 在工作笔记或组会中报告“观察到什么、缺什么、下一步验证什么”。 | 当作确认性结果、项目最终决定或方法优越性证据。 |
| **V2 `AUDITABLE_RESULT`** | 协议和输入已冻结，计划运行都有状态，失败与排除可见，数字可重算，边界明确。 | 形成可审计结果包；在权限允许时共享 artifact，并报告精确协议内观察。 | 因为 artifact 可运行就声称机制、泛化、效率或创新成立。 |
| **V3 `DECISION_EVIDENCE`** | 在 V2 基础上，baseline 公平、规模与目标相称、不确定性和替代解释已检查，关键结果经另一人按约定深度复核。 | 支持限定范围的项目决定、阶段报告或下一轮资源投入。 | 自动进入摘要 / 结论，或推广到未覆盖的数据、模型、场景与总体。 |
| **V4 `MANUSCRIPT_CLAIM_READY`** | 每条精确主张通过结果—主张审计；所需消融、稳健性、外部有效性或理论证据与主张类型匹配；正文、图表、补充材料和冻结结果一致，并完成作者团队与 venue 检查。 | 把 `verified / qualified` 的精确表述写入相应论文位置。 | 宣称已被同行接受、独立复现或普遍成立；这些需要额外外部证据。 |

验证等级按“最弱的关键环节”决定。五个 seed 不能补救错误数据划分，漂亮误差条不能补救事后挑选，代码公开不能补救不公平 baseline，组会认可也不能把探索性发现变成预设检验。这里的 V0–V4 只描述结果验证成熟度，与[产物生命周期](EXPERIMENT_ARTIFACT_LIFECYCLE.md)中的 `E2_EVIDENCE` 文件保留类别不是同一轴。

## 3. 共享权限 S0–S3

| 等级 | 允许受众 | 最低条件 |
| --- | --- | --- |
| **S0 `PRIVATE_RESTRICTED`** | 仅明确获授权的个人或受限环境。 | 涉及个人数据、受限数据、私有代码、匿名审稿、未公开稿件、安全细节或合同限制。 |
| **S1 `TEAM_ONLY`** | 课题组或项目内部。 | 团队负责人、存储位置和成员访问范围明确；材料仍可能包含未公开研究。 |
| **S2 `CONTROLLED_COLLABORATOR`** | 指定合作者、评审或受控 artifact 环境。 | 接收者、目的、期限、可下载 / 可转发范围和必要协议明确。 |
| **S3 `PUBLIC_VIEWABLE`** | 公开互联网。 | 公开行为符合数据、代码、匿名和 venue 规则；敏感信息已检查，许可证或“尚无许可证”的状态已明确。 |

`S3` 只说明“允许公开查看”。GitHub 仓库公开不自动授予复制、修改或再分发权；可复用范围由许可证、数据条款和第三方组件共同决定。高证据也可能只能是 `S0`，低证据也可能被公开展示为明确标注的教学或失败案例。

## 4. 从两个轴得到本次状态

先判 V，再判 S，最后选择本次用途状态：

| 状态 | 进入条件 | 对外表述要求 |
| --- | --- | --- |
| `HOLD_PRIVATE` | 共享授权不清、包含受限材料，或匿名 / 安全规则要求暂停。 | 不外传；先删减、匿名化或请求授权。 |
| `INTERNAL_DEBUG` | V0；或 V1 但只用于排障。 | 说“出现了信号 / 尚未核验”，不得说“证明”。 |
| `MEETING_PRELIMINARY` | V1 以上且受众不超过当前 S。 | 同时展示协议状态、失败项、验证等级、替代解释和具体反馈请求。 |
| `SHAREABLE_ARTIFACT_ONLY` | 至少 V2，且接收者在 S 范围内。 | 可以说 artifact 可定位 / 可执行到何种深度；不得把“可运行”改写成科研主张成立。 |
| `DECISION_READY` | 至少 V3，决定对象与证据覆盖一致。 | 写清选择、代价、未覆盖范围和重开条件。 |
| `MANUSCRIPT_CLAIM_READY` | V4，具体 `claim_id` 为 `verified / qualified`，作者与提交规则允许。 | 只使用审计后的精确句子和对应限制。 |

状态不是奖章。`MEETING_PRELIMINARY` 可以是高质量进展；`HOLD_PRIVATE` 也可能包含很强证据。目标是让表达、受众和证据匹配，不是让所有结果尽快升到 V4 / S3。

## 5. 四种常见场景

### 组会或导师汇报

组会可以接收 V0–V4，但必须让听众知道它是哪一级。推荐一页内写：

```text
本页状态：V1 TRACEABLE_OBSERVATION / S1 TEAM_ONLY
观察：在什么固定条件下看到了什么
缺口：哪些运行、对照或核验尚未完成
当前允许表述：一句精确限定句
请求：希望听众判断哪个问题
```

不要为了显得有进度隐藏失败运行，也不要把导师的口头认可登记成 V4。反馈改变协议或主张后，使用[反馈闭环](MENTOR_FEEDBACK_LOOP.md)并重新评级。

### 发给合作者或公开 artifact

至少核对：唯一入口、版本、输入、运行状态、许可证 / 条款、敏感信息、接收者权限和到期策略。artifact 达到可用或可复查，只证明交付质量；是否支持论文主张仍由 V 等级和 `claim_id` 决定。

公开页面应同时给出：

- 这是 debug、pilot、复现、确认实验还是教学示例；
- 哪些命令与结果已经实际运行；
- 哪些内容没有核验或无法公开；
- 允许引用的限定表述与禁止外推；
- 许可证和第三方资产边界。

### 项目继续、转向或停止

V3 用于支持一个明确决定，不要求所有问题都解决。决定记录必须说明：当前证据覆盖什么、资源和风险代价、被否定的备选、触发重开的新证据。V1 的 pilot 可以决定“是否值得做下一次确认实验”，但不能直接决定“方法已经有效”。

### 写论文

论文可如实记录负结果、失败、pilot 或局限，但这些内容不能伪装成 V4 正向主张。对每条进入摘要、引言、结果或结论的核心表述：

1. 绑定唯一 `claim_id`；
2. 说明主张类型与覆盖总体；
3. 链接冻结结果、图表生成链、反证与替代解释；
4. 确认状态为 `verified / qualified`；
5. 由有决定权的作者复核，并按当届 venue 清单再次检查。

“写进论文”只表示作者团队当前认为证据足以支撑精确表述，不表示评审、读者或独立团队已经验证。

## 6. 允许句与禁止句

| 当前状态 | 可以写 | 不应写 |
| --- | --- | --- |
| V0 | “一次调试运行出现该数值，尚未核验配置和重复性。” | “模型已经提升。” |
| V1 | “pilot 中观察到差异，将按冻结协议确认。” | “实验表明方法有效。” |
| V2 | “在已列条件与全部计划运行中观察到该差异；结果包可重算。” | “代码开源，因此结论可信。” |
| V3 | “该证据支持在当前项目范围内进入 / 停止下一阶段。” | “结果可推广到所有任务。” |
| V4 | “在列明数据、模型、预算和评价范围内，候选方法……；限制为……” | “全面领先、普遍有效、证明机制正确。” |

最强词不等于最专业。`可能、观察到、在……范围内、与……一致、尚不能排除` 只有在准确反映证据时才使用，也不能靠模糊词替代具体边界。

## 7. 升级、降级与失效

每次升级都要增加新证据，而不是只改标签：

```text
V0 → V1：补身份、版本、命令、run_id 和原始输出
V1 → V2：冻结协议，完成全部计划运行并可重算
V2 → V3：补公平性、代表性、替代解释和独立复核
V3 → V4：逐 claim 匹配证据，完成作者与 venue 审查
```

出现以下任一情况应立即降级或标记失效：数据 / split 错误、评测实现变化、遗漏失败运行、测试集参与选择、结果文件被覆盖、关键 artifact 失效、共享权限撤回、图文数字不一致、主张范围扩大或发现未披露的额外搜索。

降级时保留旧状态、原因、日期和受影响输出。已经发出的幻灯片、报告或草稿要记录哪些页面和句子需要更正，不能只在最新文件里静默修改。

## 8. AI 辅助边界

AI 可以整理运行清单、检查缺失字段、生成限定句候选和比对图文数字，但不能自行确认：

- 某次运行真实执行且未被选择性保留；
- 数据、代码、匿名材料和作者身份允许共享；
- 一个结果达到 V3 / V4；
- 一条机制、泛化、因果或创新主张成立；
- 导师、合作者、venue 或数据权利方已经批准公开。

自动生成的论文、图表或验证报告首先是待审 artifact。阶段数量、多个 agent、自动 review 分数和“conference-ready”文件名都不能替代作者对证据和权限的核验。

## 9. 经验与规范依据

- [研究生的实验记录该怎么记，以结果为导向](https://www.xiaohongshu.com/explore/696fa4fb000000001a02bc8e)反映流水记录难以支撑汇报；本指南吸收“面向问题和结果组织”，但要求结果仍链接完整运行与失败项；
- [科研习惯分享（三）：一次实验我写 3 份记录](https://www.xiaohongshu.com/explore/6612bab8000000001b013f7e)区分随手记录、复盘和汇报用途；本指南保留一个证据来源、按受众生成不同视图，不要求复制三套事实；
- [知乎：深度学习实验是否可以汇报多次测试中的最高准确率](https://www.zhihu.com/en/answer/3249240394)中的回答对最高值、均值和随机种子存在分歧，说明个人经验不能定义报告协议；应以运行前规则、完整分布与目标 venue 要求为准；
- [知乎：你们实验室的例会制度是怎样的](https://www.zhihu.com/question/322279340)反映“定期汇报”可能退化成进度比较；本指南把等级、缺口和反馈请求作为汇报入口，不评价具体实验室制度；
- [Learning Research](https://github.com/pengsida/learning_research)把做实验、论文写作和 presentation 视为相互连接但不同的科研能力，并明确内容来自特定实验室经验；本指南吸收持续实践与交流，不把周频率、3D Vision 路线或个人表达方式设为通用规则；
- [AutoResearchClaw](https://github.com/aiming-lab/AutoResearchClaw)展示阶段产物、人类门控、验证报告、实验运行和自动生成论文；本指南借鉴阶段化与可定位产物，同时明确自动 pipeline 的完成状态不是 V4；
- [AAAI-26 Reproducibility Checklist](https://aaai.org/conference/aaai/aaai-26/reproducibility-checklist/)要求区分事实、观点、假设与推测，并报告随机性、运行次数、指标和主张所需信息；
- [REFORMS](https://reforms.cs.princeton.edu/)把有效性、可复现性、泛化范围和报告透明度分开检查，支持按主张总体限制表达；
- [ACM Artifact Evaluation 示例](https://sigsim.acm.org/conf/pads/2024/blog/artifact-evaluation/)区分 artifact 可得、功能 / 可复用与结果被复现，说明“能共享”与“结论被验证”不是同一等级；
- [Improving Reproducibility in Machine Learning Research](https://www.jmlr.org/papers/v22/20-303.html)总结选择性报告、适应性过拟合和超出证据范围的主张风险；
- [Releasing Research Code](https://github.com/paperswithcode/releasing-research-code)要求结果表与精确训练、评测命令对应，支持可共享 artifact 的最低执行链。

经验帖用于发现新手真实痛点，不能替代项目、机构、数据提供方、作者团队和目标 venue 的当前规则。

## 10. 完成标准

在汇报、共享、决策或写作前，你应能拿出：

- 一个明确的输出对象与受众；
- 一个 V 等级及其缺失检查；
- 一个 S 等级、授权依据和许可证 / 条款边界；
- 一句允许表述与一句禁止表述；
- 对应 `run_id`、冻结结果、主张审计或交接证据；
- 一个用途状态，以及升级、降级或重开的触发条件。

第一次不知道如何填写时，查看[教学演练证据等级示例](../examples/first-workflow-drill/evidence-readiness.md)，再把同样判断映射到真实项目现有记录中。
