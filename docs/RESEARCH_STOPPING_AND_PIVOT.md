# 负结果、无进展与研究停止门

这份指南用于实验连续不提升、反复报错、预算接近耗尽，或一项结果已经回答当前问题时，决定继续、收缩、转向还是停止。它审查的是一个明确的研究问题或实验族，不评价一个人是否适合科研，也不把一次失败扩大成对整个课题或职业的结论。

```text
先判结果性质 → 再判是否存在有区分力的下一步 → 检查预算与风险
              → PROCEED / REFINE / PIVOT / STOP
```

> 停止不是删除证据，继续也不是重复同一动作。每次新增运行都必须说明它将排除什么解释、改变什么决定。

## 1. 先分清五类结果

| 结果类别 | 判断依据 | 能说明什么 | 下一步 |
| --- | --- | --- | --- |
| `INVALID_RUN` | 数据、代码、协议、指标或运行链路失效，结果不能按计划解释。 | 只说明执行链需要修复，不支持或反驳研究假设。 | `REFINE`：定位首个关键失效并设计一次修复验证。 |
| `VALID_NEGATIVE` | 预先声明的协议有效且运行完整，但目标效应、门槛或预测未得到支持。 | 当前范围内缺少预期支持；不能自动证明“效应为零”或“方法永远无效”。 | 通常 `STOP + ANSWERED`；若替代假设有新证据，再 `PIVOT`。 |
| `INCONCLUSIVE` | 不确定性过大、样本或重复不足、结果不稳定、关键混杂未排除。 | 目前无法判断支持或不支持。 | 只有存在可执行且有区分力的补充检查时才 `REFINE`。 |
| `POSITIVE_BOUNDED` | 预设门槛在冻结范围内达到，完整性与公平性检查通过。 | 支持限定协议内结论，不自动支持机制、泛化或论文贡献。 | `PROCEED` 到确认、真实 baseline 或下一问题；当前实验族可 `STOP + ANSWERED`。 |
| `RISK_OR_POLICY_STOP` | 权限、伦理、隐私、安全、匿名、许可证或不可接受副作用触发停止。 | 当前动作不能继续，不等于科学假设被反驳。 | `STOP + RISK` 并向有决定权的人升级。 |

无效运行和有效负结果必须分开。报错、错误 split 或指标实现问题不能写成“方法失败”；反过来，协议有效但没有达到预设效果，也不应被隐藏成“再调一次就会好”。

## 2. 什么才算一次有效尝试

一次 **material attempt（有信息增量的尝试）** 至少满足一项：

- 改变一个能够区分竞争解释的变量；
- 修复一个已定位的协议失效，并验证修复是否成立；
- 增加能够显著收窄不确定性的样本、重复或对照；
- 在不改变原主张的前提下，进入预先计划的更代表性规模；
- 检查一项会改变继续、转向或停止决定的风险或资源假设。

以下动作不计为新的有效尝试：不改变诊断就重复同一失败命令；测试结果可见后随意换 seed、阈值或切片；只增加训练轮数却没有预测；同时修改多个变量后挑最好结果；因为投入很多而继续消耗预算。

最低尝试台账：

| 字段 | 要回答的问题 |
| --- | --- |
| `attempt_id` | 这次尝试如何被唯一定位？ |
| 当前问题与预测 | 运行前预计哪种结果将支持或反驳什么？ |
| 唯一新增信息 | 它比上一轮多区分了哪个解释？ |
| 改动与固定项 | 改了什么，哪些关键条件不变？ |
| 证据与成本 | `run_id`、日志、结果、时间、算力或费用在哪里？ |
| 结果类别 | 五类结果中的哪一类，依据是什么？ |
| 已排除与未排除 | 哪些解释已不再合理，哪些仍开放？ |
| 决定影响 | 这个结果是否真的改变下一步？ |

## 3. 运行前冻结复查触发器

不要等到精疲力尽才讨论停止。实验卡至少预先写明：

- 最大 trial 数、计算 / 费用预算、截止日期和负责人；
- 什么结果视为支持、有效负结果或证据不足；
- 哪些失效允许修复，修复后需要什么最低验证；
- 哪些关键假设一旦被反驳就转向；
- 哪些权限、安全或数据问题立即停止；
- 何时进行阶段复查，而不是自动启动下一轮。

固定次数只能是本项目预算，不能包装成普适规律。出现以下任一情况时应立即进入停止门，不必等待预设日期：

1. 同一阻塞重复出现，且新一轮没有新增诊断证据；
2. 连续尝试只产生相同结论，下一项运行不会改变决定；
3. 关键机制假设、数据可用性或 baseline 合法性已经被反证；
4. 剩余预算不足以完成一次有解释力的验证；
5. 测试集、评价协议或主张被事后修改，原比较需要降级；
6. 权限、伦理、隐私、安全或许可证边界被触发；
7. 当前问题已经被有效回答，包括得到有效负结果。

## 4. 五个停止门问题

每次复查按顺序回答：

### G-S1 协议是否有效

- 数据身份、split、代码、环境、评价和完整运行是否可核验？
- 失败运行是否都保留状态，是否存在选择性排除？
- 如果无效，是否已经定位到可验证的单一修复？

无效且没有具体修复假设时，不得靠增加运行数“冲出一个结果”。

### G-S2 下一步是否有区分力

用一句话写出：

```text
如果执行 X，出现 A 将支持解释 1，出现 B 将支持解释 2；两种结果会导致不同决定。
```

写不出 A、B 和对应决定，说明下一轮多半只是动作，不是实验。

### G-S3 边际信息是否值得成本

- 上一轮减少了哪个不确定性？
- 下一轮预计新增什么，而不是只提高一个小数？
- 这个信息是否足以改变项目、主张或资源决定？
- 收缩数据、模型、假设或评价范围能否用更低成本回答问题？

已经达到当前教学、复现或阶段目标时，应进入下一里程碑，不为追求更漂亮数字继续事后搜索。

### G-S4 剩余预算能否完成闭环

剩余预算必须覆盖“运行 + 失败重试 + 汇总 + 复查 + 归档”，不能只够启动训练。预算不足时选择缩小可回答问题、延期申请资源或 `STOP + BUDGET`，不得删掉必要对照来制造完成。

### G-S5 权限与风险是否允许继续

技术上能运行不代表被授权继续。涉及新数据、付费 API、共享服务器、对外发布、删除远端产物或改变共同 baseline 时，重新检查任务授权；风险门触发后由有决定权的人处理，AI 不得自动批准。

## 5. 四类决定与原因码

只选择一个顶层决定，并附一个原因码：

| 决定 | 原因码 | 适用情形 |
| --- | --- | --- |
| `PROCEED` | `CONFIRMATORY_READY` / `NEXT_MILESTONE_READY` | 当前证据达到预设门槛，进入确认实验或下一里程碑。 |
| `REFINE` | `INVALID_PROTOCOL` / `SCOPE_TOO_BROAD` / `ONE_DISCRIMINATING_TEST` | 仍有一个明确、可负担且会改变决定的修复或检查。 |
| `PIVOT` | `HYPOTHESIS_REFUTED` / `BASELINE_UNSUITABLE` / `EXTERNAL_CONSTRAINT_CHANGED` | 当前路线核心前提失效，但已有资产支持新问题或备选路线。 |
| `STOP` | `ANSWERED` / `BUDGET` / `RISK` / `NO_DISCRIMINATING_TEST` | 问题已回答、资源无法闭环、风险不允许，或没有能改变决定的下一项实验。 |

`REFINE` 不是无限续期。它必须绑定一项有效尝试、预算和完成信号；下一次复查仍写不出有区分力的实验时，转为 `PIVOT` 或 `STOP`。`PIVOT` 也不是静默改目标：要冻结旧问题、旧协议、旧结果和转向理由，再新建研究问题与预算。

## 6. 把负结果变成可复用证据

停止后至少保留：

- 原问题、假设、非目标和预设门槛；
- 论文 / baseline / 数据 / 代码 / 环境身份；
- 全部计划尝试及 completed、failed、pruned、excluded 状态；
- 无效运行与有效负结果的分界及修复记录；
- 汇总结果、不确定性、失败案例和替代解释；
- 当前最强可辩护结论，以及不能声称什么；
- 已消耗与剩余资源；
- 顶层决定、原因码、负责人和日期；
- 产物保留位置与重开触发器。

重开触发器应是新证据或条件变化，例如获得新数据、修复已确认的上游缺陷、取得足以完成协议的资源、出现可检验的新理论，或独立结果与当前结论矛盾。“过了一段时间”“已经投入很多”或“再试一个参数”不是重开依据。

负结果可以支持“在列明协议与范围内未达到预设门槛”，但通常不能支持“没有任何效应”“该方向不可能成功”。若要证明实际等价、非劣或效应小于某个可接受界限，需要相应统计设计，不能从未显著或单次失败直接推出。

## 7. 周会中的最短表达

```text
问题：本轮试图区分什么？
状态：INVALID_RUN / VALID_NEGATIVE / INCONCLUSIVE / POSITIVE_BOUNDED / RISK_OR_POLICY_STOP
证据：新增了哪项可定位结果，排除了什么？
成本：已用 / 剩余预算，能否完成下一次闭环？
决定：PROCEED / REFINE / PIVOT / STOP + 原因码
请求：需要负责人批准、补充资源，还是确认归档？
```

“本周没有提升”不是空白进度；如果协议有效、竞争解释被排除、停止决定有依据，它就是可审计结果。反之，运行很多但无法说明新增信息，也不能算有效进展。

## 8. AI 辅助边界

AI 可以汇总尝试台账、发现重复运行、估算已记录成本、列出竞争解释和生成决定草案，但不能自行判断：

- 未实际运行的实验已经失败或成功；
- 负结果证明效应不存在；
- 修改测试集、指标或排除规则是可接受的；
- 额外预算、数据访问、付费调用或公开行为已获授权；
- 团队应终止课题、学生应放弃方向或作者应撤回论文。

停止门只管理当前研究单元。涉及人员评价、学业安排、合作关系或重大资源承诺时，必须由相应负责人结合完整背景决定。

## 9. 经验、项目与规范依据

- [科研探索目的下 Codex 老在奇怪的地方使劲](https://www.xiaohongshu.com/explore/6a76af7d000000002500743e)反映 AI 容易扩张任务和过度实现；本指南用唯一问题、最大范围和信息增量限制继续运行，不把个案中的具体工具表现推广到所有模型；
- [跑 baseline 常见的坑](https://www.xiaohongshu.com/explore/6925b658000000001d03acfb)反映环境、数据、评价与方法失败容易混在一起；本指南先判 `INVALID_RUN`，再讨论假设，不把经验帖当作具体项目的复现标准；
- [研一暑假做实验才发现，数据管理比调参更重要](https://www.xiaohongshu.com/explore/6a5f37be00000000110120f5)强调缺少数据版本、划分和设置会导致反复核对；本指南要求停止决定绑定可定位证据，而不是只保留最好权重；
- [研究生的实验记录该怎么记，以结果为导向](https://www.xiaohongshu.com/explore/696fa4fb000000001a02bc8e)反映流水笔记难以支持判断；本指南按问题、尝试、证据和决定组织，但“结果导向”不等于只保留正结果；
- [知乎：负面结果怎么写？让失败实验也有发表价值](https://zhuanlan.zhihu.com/p/1973701811283195210)区分负结果与执行失败，并提示失败也可形成经验；该文属于二手经验内容，只用于确认术语混淆，不作为统计或发表规则；
- [知乎：我的博士生已经半个月没主动联系我了，怎么能让他更主动一点？](https://zhuanlan.zhihu.com/p/2058886370387571300)反映长期卡住时可能延迟暴露问题；个人导师经验只用于说明应及时形成可讨论证据，不规定组会频率或师生责任；
- [Learning Research](https://github.com/pengsida/learning_research/blob/master/getting_advanced_in_research.md)把实验能力包含编码、分析实验为何不工作和实验记录；它是特定研究者与实验室经验，本指南不照搬研究方向、训练年限或组织方式；
- [AutoResearchClaw](https://github.com/aiming-lab/AutoResearchClaw)展示阶段化 `PROCEED / REFINE / PIVOT`、人工门控、版本化 artifact 与预算保护；固定迭代轮数和费用阈值是该系统的实现配置，不是通用科研停止标准；
- [Deep Learning Tuning Playbook](https://github.com/google-research/tuning_playbook)讨论有限预算、试验方差、曲线诊断和改进收益与复杂度的权衡；本指南据此要求边际信息与完整 trial 台账，但具体搜索空间和运行数必须按任务确定；
- [Position: Embracing Negative Results in Machine Learning](https://arxiv.org/abs/2406.03980)讨论机器学习中方法未获预期支持、复现失败模式和负结果公开的价值，并强调需排除实现质量问题；它是立场论文，其负结果分类和统计语义不能替代具体研究设计；
- [ORI：Selective Reporting of Results](https://ori.hhs.gov/selective-reporting-results)提醒按预先计划报告，并披露和解释事后分析、异常值处理与方法改变；
- [Fostering Integrity in Research](https://www.ncbi.nlm.nih.gov/books/NBK475939/)讨论不报告负结果与只保留正结果造成的偏差，并指出负结果可暴露方法缺陷和减少无效重复。

经验帖用于发现新手痛点；GitHub 项目用于对照可执行机制；机构、正式方法规范、任务授权与目标 venue 规则决定最终要求。

## 10. 完成标准

一次继续、收缩、转向或停止决定至少应拿出：

- 一个明确的研究问题或实验族；
- 一个结果类别及其协议有效性证据；
- 一份不遗漏失败、剪枝和排除项的尝试台账；
- 一项确有区分力的下一步，或“没有下一项”的证据；
- 已用与剩余预算、风险和授权状态；
- 一个顶层决定、原因码和负责人；
- 当前最强允许表述、不能声称什么、产物位置和重开触发器。

第一次不知道如何停止时，查看[教学演练停止决定](../examples/first-workflow-drill/stopping-decision.md)：它演示为什么“结果很好”也可能意味着当前问题已经回答，应停止继续调玩具参数并进入真实 baseline。
