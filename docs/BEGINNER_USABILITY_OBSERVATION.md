# 零基础首次使用可用性观察

这份指南供维护者、导师或学习小组观察一位未参与仓库编写的新读者。目标不是测试参与者掌握了多少科研知识，而是判断仓库能否让目标读者找到第一步、完成最小演练并在失败时找到帮助。

自动脚本、链接检查和编写者自测只能证明仓库内部一致，不能替代真人观察。没有真实观察记录时，不应写“已通过零基础用户验证”。

## 适用范围

- **目标读者**：自述第一次接触计算机 / AI 科研，或尚未独立完成可检查实验的人；
- **测试对象**：根 README 的默认入口、准备检查、L0 分流、第一次演练和求助出口；
- **不测试**：个人智力、学习速度、研究潜力、某门课程质量或第三方项目安装；
- **最低产物**：一次匿名观察记录、明确卡点和一个可验证的仓库改进行动。

同一位熟悉仓库的人反复执行只能用于回归检查，不能继续算作陌生读者证据。若要判断 Windows、macOS、Linux 或辅助技术体验，应分别记录实际条件，不能从一种环境外推。

## 开始前约定

1. 明确说明“测试的是仓库，不是你”，参与者可以随时跳过问题或停止；
2. 不收集姓名、学校、实验室、导师、账号、精确个人路径等非必要信息；
3. 默认只做文字笔记。录音、录像或录屏必须另行取得明确同意，并说明保存位置、访问者和删除时间；
4. 使用合成数据和本仓库公开内容。不得要求参与者展示密钥、内网、私有仓库、受限数据、未公开论文或审稿材料；
5. GitHub Issue 是公开记录。参与者不愿公开时，由观察者保存脱敏摘要，并只提交不含身份信息的仓库问题。

## 给参与者的任务

将下面任务逐条给出，不提前说出文件名、按钮文字或正确路线：

```text
从仓库首页开始，请找到适合第一次使用者的起点。
请按仓库说明推进，直到完成第一次演练，或你决定停止。
如果完成，请找到配置、环境、指标和日志四类产物，并解释它们分别回答什么问题。
如果卡住，请尝试找到仓库提供的帮助入口。
过程中请说出你准备做什么、为什么这样选择；不知道也可以直接说不知道。
```

任务说明必须保持中性。不要说“点准备检查表”“你应该进入 L0”或“答案就在某一节”。参与者完全卡住后可以提供一次帮助，但必须先记录卡点和帮助内容。

## 观察什么

只记录看到或听到的行为，不先替参与者解释原因：

- 第一眼认为仓库解决什么问题；
- 第一个点击、命令或决定，以及选择理由；
- 犹豫、回退、误入资源目录、同时打开多条路线或跳过前置检查的位置；
- 第一个不理解的词、命令和报错；
- 是否自行找到仓库内帮助，还是转向搜索、AI、同伴或直接停止；
- 是否能找到四项产物、实际解释器和输出目录；
- 参与者原话，以及观察到的具体页面或步骤。

一次笔记只写一个观察。将“参与者先打开资源目录，停留约一分钟后返回”与“资源太多导致焦虑”分开：前者是观察，后者仍是待验证解释。

## 最小观察记录

```text
观察编号：U-YYYYMMDD-01
仓库 commit：
系统与入口：例如 Windows 11 / GitHub 网页；不记录个人路径
起始状态：工具不会 / 能运行 Python / 跑过代码 / 已有任务 / 不愿说明

首次动作：
首次犹豫或卡点：
使用的帮助：仓库内 / 搜索 / AI / 人员 / 无
观察者提供的提示：无；或写出原话与发生时点
最终状态：从下方状态码选择一个
可核验观察：
待验证解释：
对应改进行动：
复查条件：由另一位陌生读者从同一任务重新开始
```

最终状态只描述本次任务：

- `COMPLETED_UNAIDED`：未使用额外帮助完成；
- `COMPLETED_WITH_REPO_HELP`：只使用仓库内说明完成；
- `COMPLETED_WITH_EXTERNAL_HELP`：依靠搜索、AI、同伴或导师完成；
- `STOPPED_BLOCKED`：已开始，但因仓库路径或说明卡住；
- `STOPPED_BY_CHOICE`：理解下一步后主动停止；
- `NOT_RUN_ENVIRONMENT`：设备、权限或网络条件阻止运行。

## 从观察到修改

按影响而不是参与者资历排序：

| 问题级别 | 处理方式 |
| --- | --- |
| `BLOCKER` | 目标读者无法继续或找不到帮助。优先建立可执行下一步并由新读者复查。 |
| `MISROUTE` | 读者稳定进入错误路线、跳过必要前置或误解完成条件。修改入口顺序或链接语义。 |
| `HESITATION` | 能继续，但必须来回比较或猜测术语。缩短选择、补充就近定义或验收。 |
| `WORDING` | 不阻止任务，但表述、示例或排版增加理解成本。进入普通文档修正。 |

每轮只把观察支持的问题写入仓库：`观察 → 问题假设 → 一项修改 → 自动回归 → 另一位陌生读者复查`。不要用同一位已经被提示过的参与者证明入口“首次可发现”，也不要从少量便利样本发布普遍成功率。

参与者可直接填写[零基础首次使用反馈](https://github.com/Starry-cz/ai-research-workflow/issues/new?template=beginner-first-use.yml)。该表单不要求外部证据或解决方案；需要修改路线、事实或规范时，维护者再补齐经验材料、官方依据和适用边界，登记到[持续改进记录](IMPROVEMENT_LOG.md)。

## 本轮完成条件

- 观察记录区分事实、解释和行动；
- 卡点对应到具体页面、文字或命令；
- 参与者未被要求公开敏感信息，也未在卡住前获得答案提示；
- 修改通过仓库自动检查；
- 由另一位陌生读者复查，或明确标记“仍待真人复查”。

没有完成最后一项时，可以说“已建立观察机制”或“本地检查通过”，不能说“已证明适合所有零基础读者”。
