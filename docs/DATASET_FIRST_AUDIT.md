# 零基础数据集审计指南

数据审计不是在训练前随手打印一次 `shape`。它要回答四个问题：这份数据从哪里来、是否有权用于当前任务、具体是哪一个版本，以及测试结果是否真的来自未见数据。

## 先做 20 分钟准入检查

在下载大文件、上传云端或运行训练前，先完成：

1. 找到原始发布页、论文、数据卡、许可证或使用条款；
2. 记录数据集名称、版本或 revision、获取日期、预计体积和访问方式；
3. 确认是否允许研究使用、修改、云端处理和再分发；
4. 确认是否含个人、敏感、受限、未公开或需要同意的数据；
5. 写出一个样本代表什么，以及准备按样本、主体、场景还是时间划分；
6. 给出 `PROCEED / REFINE / STOP`。

“网页能打开”“别人把文件传给我”“代码会自动下载”都不能替代授权和来源核验。不知道许可证时写“未知”，不要猜成“仅科研使用”或默认开源。

## 建立数据身份

至少记录：

```text
dataset_id / config / split
原始发布者与原始链接
版本、revision、发布日期与获取日期
文件名、字节数、校验值或官方 manifest
下载或生成命令
原始存储位置与访问权限
处理脚本 commit、配置与输出版本
```

校验值只能证明文件是否相同，不能证明数据正确、合法或没有偏差。平台上的 `latest`、同名压缩包和不断更新的网页不是稳定版本；可用时锁定 tag、revision、DOI、官方 release 或文件清单。

## 先定义“一个样本是什么”

在划分前写清：

- 一个样本代表一张图、一段文本、一次交互、一个患者的一次检查，还是完整受试者；
- 多行数据是否来自同一人、视频、文档、设备、地点、会话或原始文件；
- 标签由谁、按什么规则产生，是否由模型生成或从其他字段推断；
- 字段的数据类型、单位、缺失含义、允许范围和输入 / 标签角色；
- 数据来自哪个总体，纳入与排除条件是什么，哪些群体或场景缺失。

逐行随机切分只适合真正独立、同分布且没有派生关系的样本。真实泛化目标决定划分单位，而不是某个通用比例。

## 选择与任务一致的划分

| 泛化目标 | 常见划分单位与主要风险 |
| --- | --- |
| 面向新的独立样本 | 样本级；仍需检查重复、近重复和增强派生关系。 |
| 面向新的受试者、用户、设备或文档 | group 级；同一 group 不能跨训练与评价集合。 |
| 面向未来数据 | 时间级；训练只使用评价时间之前可获得的信息，必要时设置时间间隔。 |
| 面向新场景、机构、语言或数据集 | 场景或域级；不能让同一来源的近似样本伪装成跨域泛化。 |

比例没有统一答案。先保证评价集合具有足够的独立单位和代表性，再结合数据规模、任务波动、交叉验证方案和目标 venue 确定数量。

划分脚本、seed、规则和最终样本 ID 清单都要版本化。看到结果后重新随机划分并挑选更好的一次，会把测试集变成选择工具。

## 最小泄漏检查

### 1. 样本与来源重叠

- 训练、验证、测试之间是否有相同 ID、文件哈希或文本；
- 是否有裁剪、增强、转码、不同分辨率、相邻帧或同一原文片段形成的近重复；
- 同一人、设备、场景、会话、文档或时间窗口是否跨 split；
- 外部预训练、检索语料或合成数据生成器是否已经包含评价样本。

### 2. 处理泄漏

数据应先划分，再让以下有状态步骤只在训练集上 `fit`：

- 缺失值插补和标准化统计；
- 词表、token 频率、特征选择和降维；
- 目标编码、类别重采样和数据驱动阈值；
- 基于全部数据挑选样本、模板、提示或难例。

验证集用于预先声明的选择，测试集只用于冻结方案后的最终评价。对测试集反复调参、选 checkpoint、改阈值或换划分，都会削弱它作为未见数据证据的作用。

### 3. 标签与时间泄漏

- 特征是否包含预测时才会知道的结果、后验统计或人工处置；
- 时间戳、文件名、路径或采集设备是否暗含标签；
- 标签生成规则是否直接或间接读取了测试答案；
- 多步预测是否错误使用未来窗口。

无法确认污染范围时，不要只删除几个明显重复项后继续。记录污染来源、受影响 split、重新划分或重建评价集的计划，并收缩结论。

## 最低质量报告

每个 split 至少报告适用项：

- 样本数、独立 group 数、时间范围和文件体积；
- 标签分布、缺失值、无效值、重复与近重复；
- 关键特征的范围、长度、分辨率或单位；
- 标注来源、标注一致性、噪声和未知标签；
- 纳入、排除、清洗、过滤和人工修订数量；
- 训练与评价集合之间的分布差异；
- 已知偏差、覆盖缺口和不适用场景。

只报告整体均值会隐藏 split 差异和小群体问题。未知信息应明确标为“未知 / 未核验”，不能写成“无”。

## 原始数据与处理数据分离

```text
raw：原始获取结果，只读，不手工覆盖
manifest：文件、校验值、版本、split ID 与访问说明
processed：由锁定脚本和配置重新生成
```

代码仓库通常只提交数据卡、manifest、处理脚本和小型脱敏样例，不直接提交大型或受限数据。密钥、个人信息、未公开数据和授权材料不要进入 Git、公开 Issue、日志或未经批准的第三方 AI 服务。

## 特殊数据仍需追加规则

- **人工标注**：记录指南、人员来源、培训、报酬、质检、分歧处理和同意；
- **网页抓取**：核对来源条款、版权、个人信息、删除机制和抓取时间；
- **合成或 AI 生成**：记录生成模型与版本、prompt / 配置、筛选、去重和人工核验，不能把合成规模当成真实覆盖；
- **医疗、教育、生物、金融或未成年人数据**：遵守所属机构审批、法规和领域规范，本通用模板不能替代伦理与法律审查；
- **动态 benchmark**：记录评价日期、版本和污染窗口，旧分数不能直接与新版本比较。

## 参考框架

- [Datasheets for Datasets](https://arxiv.org/abs/1803.09010)：用动机、组成、收集、处理、用途、分发和维护说明数据生命周期；
- [Hugging Face Dataset Card Guide](https://github.com/huggingface/datasets/blob/main/templates/README_guide.md)：提供结构、字段、split、来源、标注、个人敏感信息、限制、许可证和引用字段；
- [scikit-learn Common Pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)：要求先划分，只在训练集上拟合预处理和特征选择；
- [scikit-learn grouped cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)：同一受试者或 group 的相关样本不能跨训练与评价集合；
- [TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)：时间任务不能用未来数据训练再评价过去；
- [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)：要求说明资产版本、许可证与条款，并在涉及人的数据时讨论同意和风险。

## 完成标准

数据可以进入正式 baseline 前，应能展示：

- 已填写的[数据集卡](../templates/13-dataset-card.md)；
- 可定位的原始来源、使用权证据、版本和文件清单；
- 可重建的划分脚本、split ID 和处理脚本；
- 分 split 的质量统计与泄漏检查结果；
- 隐私、偏差、未知信息和禁止用途；
- `PROCEED / REFINE / STOP` 及其证据位置。

如果这些信息来自上游且无法自行验证，应保留“上游声明”和“本地已验证”两个标签，不要把引用数据卡写成自己完成了全部审计。
