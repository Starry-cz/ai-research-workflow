# 运行交接与冷启动复查

这份指南用于把一次关键运行交给导师、合作者或未来的自己复查。目标不是再写一份实验日报，而是让接收者只从一个入口出发，能够找到证据、核验声明的结果，并在约定深度内继续工作。

## 什么时候启用

只在以下事件发生时启用：

- 关键运行准备进入组会、报告、论文图表或阶段决策；
- 项目将换电脑、服务器、负责人或暂停两周以上；
- 结果只存在于个人电脑、私有 tracker、临时云盘或口头说明中；
- 合作者需要复算指标、最小复跑或正式接管项目。

普通调试运行不需要逐条制作交接卡。已有实验室平台能够承载这些字段时，只补入口和缺失项，不建立第二套台账。

## 先声明交接深度

| 深度 | 接收者应完成什么 | 适合场景 |
| --- | --- | --- |
| `H0_LOCATE` | 找到当前状态、代码、数据说明、运行和决定 | 周会浏览、项目暂停前保存入口 |
| `H1_VERIFY` | 从已有且获准访问的产物重算至少一个关键指标 | 导师复核结果、图表制作前检查 |
| `H2_REPLAY` | 在新目录或另一台机器运行最小命令并得到预期信号 | 服务器迁移、协作者复现入口 |
| `H3_TAKEOVER` | 在 H2 基础上取得所需权限，理解待办、风险和负责人，可以继续下一项工作 | 毕业、换组、长期协作或负责人变更 |

深度必须与用途相称。复查一个图表通常不需要重跑完整训练；声称“另一人可以接手”则不能只发送 tracker 链接。

## 建立唯一交接入口

在项目 README、内部 Wiki 或一张[运行交接卡](../templates/16-run-handoff.md)中指定唯一入口。入口至少回答：

| 对象 | 必须指向的主要来源 |
| --- | --- |
| 当前状态 | 一句话结论、当前决定、未解决问题和下一步 |
| 代码 | 仓库、分支、commit、工作区是否有未提交 diff |
| 环境 | 锁定文件、Python / CUDA / 系统边界和安装命令 |
| 数据 | 来源、revision、split、校验值、使用限制和获取负责人 |
| 配置 | 实际配置路径或快照及其指纹 |
| 运行 | 唯一 `run_id`、命令、工作目录、状态和日志 |
| 产物 | URI / 路径、类型、大小或校验值、保留期限和访问状态 |
| 指标 | 评价脚本、重算命令、预期值、容差和统计单位 |
| 决定 | 采用、继续、转向或停止的证据与主张边界 |
| 权限 | 哪些内容公开、受限或不可转发，以及向谁申请；不记录密钥本身 |

同一事实只保留一个主要来源。交接卡链接真实 config、tracker 或产物，不手抄一份可能过期的副本。

发现平台 TTL、服务器回收、存储告警或项目结题时，先按[实验产物生命周期](EXPERIMENT_ARTIFACT_LIFECYCLE.md)分类和检查引用，再更新交接状态；不能让仍显示 `HANDOFF_READY` 的入口指向已清理资产。

## 冷启动复查

“作者自己还能运行”不等于完成交接。指定接收者，或由维护者模拟一个没有本地缓存的新接收者，执行：

1. 从空目录或新机器打开唯一入口，不接受作者口头补充；
2. 检出声明的 commit，确认工作区和依赖身份；
3. 按权限说明取得允许共享的数据、权重或结果；
4. 先运行最快的帮助、测试、预训练评测或合成数据命令；
5. 从冻结产物重算一个关键指标，并按预设容差比较；
6. 能用一句话复述当前决定、证据边界和未解决问题；
7. 在交接卡记录缺失入口、权限阻塞、结果差异和实际耗时。

冷启动发现的缺口应回写唯一入口，不靠私聊补丁长期维持。

## 交接结果只作一个决定

| 状态 | 含义与下一步 |
| --- | --- |
| `HANDOFF_READY` | 声明深度全部通过，接收者能够按入口复查。 |
| `REVIEW_ONLY` | 合法的算力、数据或许可限制只允许 H0 / H1；已明确不能据此声称可完整复跑。 |
| `NEEDS_ACCESS` | 必要资产或平台权限尚未取得；记录负责人和申请路径，不发送密钥。 |
| `STALE_REFERENCE` | commit、路径、配置、数据 revision 或产物已经漂移；先修正唯一来源。 |
| `REPLAY_FAILED` | 入口可用但命令、指标或容差未通过；保留日志并回到复现或调试。 |

`REVIEW_ONLY` 是透明降级，不是伪装成复现成功。受限数据项目可以交付代码、合成样例、schema、校验脚本和结果摘要，但必须写清哪些步骤无法由接收者独立验证。

## Tracker 与云平台边界

MLflow、Weights & Biases 或其他 tracker 可以保存 run ID、配置、指标和产物，但链接本身不等于可交接：

- 显示名称可能不唯一，应保留稳定 run ID；
- 代码 commit、数据 revision、artifact store 和评价脚本仍要能够定位；
- 接收者可能没有账号、项目权限或原机器上的本地文件；
- 产物可能过期、被清理或只保存在本地后端；
- 平台页面展示的汇总值仍应能由冻结结果重算。

因此交接入口要同时记录身份、访问条件、复查命令和保留策略，不把第三方页面截图当作唯一证据。

## 最低验收清单

- [ ] 已指定接收者、用途和 H0–H3 深度；
- [ ] 唯一入口包含当前决定和所有主要来源链接；
- [ ] commit、环境、数据、配置、运行和产物身份可以相互定位；
- [ ] 权限和申请负责人明确，文档中没有密钥或受限内容；
- [ ] 至少一个指标有可执行的重算方式和预设容差；
- [ ] 已在空目录或另一台机器执行相应深度的冷启动复查；
- [ ] 差异、失败和无法公开的边界已经记录；
- [ ] 最终状态只选择一种，并写明下一次重新检查的触发条件。

## 依据与延伸阅读

- [The Turing Way：可复现与协作项目](https://book.the-turing-way.org/project-design/pd-overview/pd-overview-repro/)：把项目状态、参与方式和可复现入口共同设计；
- [Good Enough Practices：协作](https://carpentries-lab.github.io/good-enough-practices/04-collaboration.html)：即使个人项目也应面向未来的合作者和未来的自己组织 README、依赖与示例；
- [MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/)：run ID、代码版本、参数、指标、状态和产物的记录模型；
- [Weights & Biases Runs](https://docs.wandb.ai/models/runs)：稳定运行身份、配置、状态、指标和产物；
- [DVC Collaborative Experiments](https://dvc.org/blog/collaborative-experiments/)：跨机器共享代码、数据、配置和实验产物时需要远端与权限；
- [Reproducibility checklist](https://ropensci-archive.github.io/reproducibility-guide/sections/checklist/)：入口、输入来源、软件版本、随机性和特定重复运行的可定位性；
- [Sustainable Research Software Hand-Over](https://arxiv.org/abs/1909.09469)：人员变动时研究软件交接的风险与按项目规模采用清单的原则。
