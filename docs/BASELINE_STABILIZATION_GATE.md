# 从 baseline 复现到首次改进

这份指南用于 M6 结束、准备进入 M7 时。它回答的不是“能不能改代码”，而是：当前 baseline 是否已经稳定到足以承担方法比较；如果没有，应该继续复现、降级用途，还是更换候选。

## 先区分三个对象

| 对象 | 含义与允许主张 |
| --- | --- |
| **论文目标值** | 论文在特定版本、数据、协议和资源下报告的结果。它是外部参照，不会自动成为你当前环境的 baseline。 |
| **本地锁定 baseline** | 未加入研究改动、在当前 commit、数据和评价协议下实际运行的结果。它是候选方法公平比较的直接对照。 |
| **候选方法** | 相对本地锁定 baseline 的唯一主要改动；必须使用同一数据、评价、预算和选择规则。 |

“候选方法优于本地 baseline”不等于“复现了论文结果”，也不等于“优于论文中的方法”。三类结果必须分别报告。

## 先写清计划达到哪种交付

- **代码学习**：理解数据流、模块、shape 与训练入口，不对论文数字或方法优越性作主张；
- **功能验证**：官方权重或最小样例可运行，只证明推理 / 评测链路；
- **训练链路验证**：短训练、保存和恢复通过，不证明完整数据上的方法效果；
- **复现研究**：完整协议达到预设容差，或差异范围和原因有可核验证据；
- **方法比较**：本地 baseline 稳定，候选改动与其执行公平对照；
- **论文主张**：还需要完整评价、重复运行、消融、反例和适用边界。

前一层的产物不能自动升级为后一层证据。

## S0：锁定身份与目标

在开始调试前记录：

```text
论文版本与目标表格 / 图 / 指标
官方仓库、branch / tag / commit
数据 revision、split 与预处理
训练与评价命令
论文报告的硬件、规模和选择规则
本地允许差异与预设容差
```

如果无法定位目标结果、数据或评价实现，当前任务只能是代码学习或资料补全，不能直接进入方法比较。

## S1：取得未修改的本地 baseline

第一次可比较运行必须满足：

- 工作区 diff 可检查；研究改动尚未混入 baseline；
- 配置、命令、环境、数据和输出目录完整保存；
- 指标能从保存预测或官方输出重新计算；
- 训练曲线、最佳 checkpoint 和选择规则可追踪；
- 失败、中断和排除运行没有被静默删除。

为了适配设备、路径或 API 而必须修改代码时，单独保存 diff，并判断它是否会改变数据、模型、优化、评价或随机性。不能把 AI 自动修改后的代码默认为“官方 baseline”。

## S2：量化复现差距

用同一协议把差距拆成可检查项：

```text
论文目标值 − 本地 baseline
  = 数据 / split 差异
  + 代码或 commit 差异
  + 环境、数值精度和硬件差异
  + 训练预算与模型选择差异
  + 评价实现差异
  + 训练随机性与未解释残差
```

这个表达是排查清单，不是假定各项可以线性相加。每一项应记录证据、排查方法和状态。

至少检查：

- 官方权重能否达到官方预期；
- 自训练结果与官方权重的差距；
- issue 中是否有同版本、同数据、同症状的报告；
- 多次本地 baseline 的中心趋势、离散和异常运行；
- 训练 / 验证曲线是否暴露欠拟合、过拟合、训练不完整或选择错误；
- 最优超参数是否落在搜索边界；
- 本地差异是否可能与候选改动发生交互。

Issue 是风险线索，不是“论文不可复现”的证明。需要核对版本、设置、维护者回复和自己的运行证据。

## S3：检查 pilot 能否升级

极小数据、少量 step 和单一 seed 只负责调试。候选方法在 pilot 上上涨，不代表完整协议会保持收益。

升级到确认性实验前至少完成：

- baseline 与候选使用相同的 pilot 抽样、预算和选择规则；
- 在一个更接近目标的数据规模或训练长度上复查方向；
- 记录效应从 pilot 到代表性规模是保持、减弱、反转还是无法判断；
- 若 full-data baseline 仍不稳定，返回 S1–S2，不继续给候选方法调参；
- 不用 pilot 反复筛选后再把同一批数据称为未见验证。

短训练超参数可能不能迁移到长训练。代表性规模的选择应依据目标协议和预算，不固定成某个百分比。

## S4：判断是否理解到可以改

在动手前应能说明：

- 输入如何经过 baseline 的主要模块并形成输出；
- 候选改动影响哪一段数据流、参数或损失；
- 哪个重复出现的现象或理论限制支持该机制；
- 预计改善哪些样本 / 条件，可能破坏哪些样本 / 条件；
- 哪个结果会否定当前解释；
- 如何回退到完全相同的本地 baseline。

不必先完成所有数学证明，但凡改动依赖某个公式、损失、归一化、注意力或概率假设，就必须理解其变量、shape、优化作用和代码映射。模块来自新论文、顶会或高 Star 仓库，都不能替代任务相关性、新颖性核验和机制证据。

## 四种门控决定

| 决定 | 条件与允许动作 |
| --- | --- |
| **READY_FOR_CHANGE** | 本地 baseline 身份锁定、运行稳定；达到预设容差，或剩余差距已被限定且不会破坏当前比较。可以提出可证伪假设并做单变量改动。 |
| **REPRODUCTION_ONLY** | 差距仍可能来自代码、数据、评价或选择规则。继续复现与诊断，禁止把候选上涨解释为方法有效。 |
| **COMPARATOR_ONLY** | 当前实现可作为同协议对照，但无法支持“复现论文”或“超过论文”的主张。必须说明来源、局限，以及差距为什么不影响当前有限比较。 |
| **REPLACE_BASELINE** | 数据 / 代码 / 评价不可得，复现差距无法控制，资源超限，或本地结果长期不稳定。保留失败记录，切换备选 baseline。 |

“差异已解释”只有在解释附带证据、残余差距有边界、且不会与研究改动混杂时，才可能进入 `READY_FOR_CHANGE`。一句推测不算解释。

## 首次改进的最小实验

```text
稳定本地 baseline
  → 一个重复失败现象或明确限制
  → 一个机制假设
  → 一个主要改动
  → 同预算公平比较
  → pilot 诊断
  → 代表性规模复查
  → 预设重复与完整评价
  → 消融、反例和回退决定
```

初次实验不要同时替换 backbone、数据增强、损失、学习率和评价阈值。baseline 原参数也不应被机械冻结：如果候选结构改变了优化条件，可以预先声明公平的调参预算，但 baseline 与候选都应获得可比机会。

## AI 修改代码时的最低要求

AI 可以帮助定位文件、生成最小补丁、补测试和解释报错，但每次修改必须留下：

- 原始现象和预期行为；
- 修改文件、diff 和理由；
- 单元 / shape / 梯度 / 小数据 / 回归验证；
- 对 baseline 公平性和评价协议的影响；
- 回退 commit；
- 研究者是否理解并接受该改动。

“代码能运行”不能区分代码错误、idea 不成立、调参不足或 pilot 偶然上涨。先验证实现，再评价研究假设。

## 完成标准

进入 M7 前应能展示：

- [首篇 baseline 准入卡](../templates/11-first-baseline-gate.md)中的稳定化记录与门控决定；
- [复现规划](../templates/03-reproduction-plan.md)中的目标、本地 baseline、差距和全部运行；
- 一张[实验卡](../templates/04-experiment-card.md)，其中 baseline run IDs、唯一改动、评价协议和规模升级条件已冻结；
- 能明确说出当前只是在学习、功能验证、复现、有限本地比较，还是支持论文级主张。

## 依据与进一步阅读

- [Deep Learning Tuning Playbook](https://github.com/google-research/tuning_playbook)：初始配置、科学变量与干扰变量、短 / 长实验、训练曲线和实验追踪；
- [Releasing Research Code](https://github.com/paperswithcode/releasing-research-code)：依赖、训练、评价、预训练权重与精确结果命令；
- [PyTorch Reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html)：版本、平台、设备与非确定性边界；
- [Lightning-Hydra-Template](https://github.com/ashleve/lightning-hydra-template)：配置化实验、日志、seed、多运行与冒烟测试的工程参考；
- [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)：训练细节、超参数选择、误差与主要实验透明度。
