# 按任务触发的数学补课指南

这不是一份要求从头学完的数学课表。它用于解决一个已经出现、并且会影响论文阅读、代码实现、实验设计或结论判断的具体问题。

```text
发现阻塞
  → 定位公式、代码或实验决策
  → 写清符号、shape、运算和假设
  → 做一个玩具数值例子
  → 与代码或数值结果核对
  → 用自己的话解释
  → 返回原来的论文或实验
```

## 什么时候触发补课

| 当前阻塞 | 优先补的内容与最低验收 |
| --- | --- |
| 不知道矩阵为什么这样乘、维度为何变化 | 线性代数；写出每个张量 shape，手算一个小矩阵例子 |
| 不知道 loss 如何影响参数、梯度从哪里来 | 微积分与优化；画出计算依赖，用有限差分或自动微分核对局部梯度 |
| 看不懂概率、似然、采样或交叉熵 | 概率与信息论；写清随机变量、条件、归一化范围和极端输入 |
| 不知道均值、方差、区间或检验支持什么结论 | 统计；明确统计单位、假设、变异来源和允许的主张 |
| 不知道归一化、距离、相似度或 PCA 的作用 | 线性代数与统计；用小数据比较处理前后的数值和信息损失 |
| 出现 `nan`、`inf`、溢出或梯度异常 | 数值计算；检查取值范围、精度、稳定实现和边界条件 |

只补当前任务需要的概念。不要因为看到“概率”就立刻学习整本概率论，也不要因为代码能运行就跳过会改变实验含义的公式。

## 五层公式阅读法

对当前公式依次回答：

1. **用途**：它在解决什么局部问题，输出会被谁使用？
2. **符号与 shape**：每个变量是什么、来自哪里、shape 和单位是什么？
3. **运算与数据流**：先执行什么、后执行什么，在哪个维度求和、平均或归一化？
4. **假设与边界**：独立性、分布、可微性、数值范围或采样假设是什么？什么时候会失效？
5. **数值与代码核对**：一个足够小的手算例子是否与实现一致？论文与代码是否使用同一版本？

先完成前两层通常就能继续扫描论文；准备复现、修改公式或据此形成结论时，应完成全部五层。

## 哪些内容可以暂缓

在不改变当前任务含义时，可以暂缓：

- 与当前模块无关的完整证明；
- 只用于更一般情形、而当前实现没有使用的扩展定理；
- 不影响实现和实验判断的历史背景；
- 需要更高阶数学、但原论文与官方实现已经给出可核验接口的推导细节。

暂缓不等于删除。把未完成部分、为什么暂缓和重新触发条件写入[数学概念卡](../templates/12-math-concept-card.md)。

## 哪些内容不能跳过

出现以下情况时，不能只复制公式或调用库：

- 修改 loss、归一化、注意力、采样、优化器或决策阈值；
- shape、广播、mask 或归约维度会改变样本含义；
- 用概率、统计检验或置信区间支持论文结论；
- 论文公式、图示与官方代码不一致；
- 出现数值不稳定、梯度异常或边界输入失败；
- 声称理论保证、复杂度优势、因果关系或统计显著性。

这时至少要核对原论文、官方代码和可靠教材；涉及统计与领域评价协议时，还要遵守目标 venue 和数据领域的规范。

## 最小数值与代码检查

一张概念卡至少完成以下检查中的适用项：

1. **shape 检查**：给每个变量写 shape，确认广播、拼接和归约维度；
2. **手算检查**：使用两三个样本或 `2 × 2` 矩阵，手算一次输入到输出；
3. **边界检查**：测试全零、相同值、极端概率、空 mask 或最小 batch 等边界；
4. **梯度检查**：修改梯度相关实现时，用有限差分或框架的梯度检查与自动微分对照；
5. **稳定性检查**：检查 `nan`、`inf`、精度、除零、对数输入和稳定等价写法；
6. **版本检查**：记录论文版本、公式编号、代码 commit、文件和函数。

有限差分、自动微分和玩具数值可以发现实现错误，但不能替代理论证明，也不能证明真实数据上的研究结论。

## 资源按问题调用

- [Mathematics for Machine Learning](https://github.com/mml-book/mml-book.github.io)：按线性代数、解析几何、矩阵分解、微积分、概率和优化查缺口，再看它们如何进入机器学习模型；
- [Dive into Deep Learning：Mathematics for Deep Learning](https://www.d2l.ai/chapter_appendix-mathematics-for-deep-learning/index.html)：需要把数学与深度学习中的梯度、概率和信息论连接时使用；
- [南瓜书 Pumpkin Book](https://github.com/datawhalechina/pumpkin-book)：阅读《西瓜书》时某个公式推导阻塞，再按公式位置查阅；
- [Neural Networks: Zero to Hero](https://github.com/karpathy/nn-zero-to-hero)：需要通过小型神经网络与反向传播代码建立数学—实现映射时使用；
- **论文原文与官方代码**：决定该项目实际使用了哪个定义、约定和实现，第三方讲解不能替代它们。

课程和教材负责建立概念，原论文和官方代码负责确认当前工作。不要把不同资料中的符号约定直接拼接。

## 使用 AI 的边界

AI 可以帮助你：

- 把符号整理成表格，提出 shape 和边界检查；
- 生成更小的数值例子或测试代码草稿；
- 对比两段推导，指出需要回到原文核验的位置。

AI 给出的推导、公式变形和代码都是待验证候选。必须回到原始定义，并用手算、测试或可靠资料核对；不要让 AI 为不存在的公式编号、定理、引用或实验结果补空白。

## 完成标准

完成一张概念卡后，你应能：

- 用一句话说出公式的目的；
- 解释主要变量、shape、运算顺序和关键假设；
- 展示一个与代码一致的玩具数值例子；
- 指出对应论文位置和代码位置；
- 说明未补内容为什么不影响当前任务；
- 回到原任务，并完成被阻塞的阅读、实现或实验决策。

如果仍无法做到，不要继续扩大学习范围。把阻塞缩小成一个公式、一个操作或一个反例，再寻求导师、同伴或课程资料帮助。
