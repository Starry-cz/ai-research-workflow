# 零基础论文发现与原文回溯

这份指南解决一个具体问题：第一次接触某个 AI 方向时，怎样在 30–45 分钟内从多个平台形成一组可核验的候选论文，而不是收藏一堆无法追踪来源的链接。

## 本轮最低产物

一次首轮检索应留下：

- 一句明确的任务描述和排除范围；
- 5–12 篇候选论文，其中 2–3 篇进入定向阅读；
- 每篇论文的稳定标识、书目记录、主版本和发现来源；
- 目标 baseline 的官方代码状态；
- 本轮查询、排除理由、停止决定和未覆盖范围。

数量是首轮任务的范围上限，不是领域覆盖标准。如果尚未形成稳定关键词，允许先保留更少的候选。

## 先分清四层来源

论文平台的职责不同。不要要求一个网站同时完成发现、版本判断和代码核验。

| 来源层 | 作用与最低记录 |
| --- | --- |
| **发现入口** | 用关键词、主题、venue、趋势或引用关系找到候选。记录平台、查询式、筛选条件和发现 URL。 |
| **书目身份** | 确认标题、作者、年份、venue、DOI 或其他稳定标识。记录 DBLP、DOI 页面或等价书目来源。 |
| **原文版本** | 确认实际阅读和引用的是哪个版本。记录出版社 / 会议页、arXiv 版本号或 OpenReview 页面及访问日期。 |
| **实现证据** | 判断代码是否由作者或项目方维护，以及它对应哪一版论文。记录仓库、commit / release、许可证、数据与评测入口。 |

最小组合是“一项发现入口 + 一项书目或稳定标识 + 一项原文版本 + 需要复现时的官方代码”。不需要把所有平台都搜索一遍。

## 三种常见起点

### 已有导师给出的论文

1. 先核验标题、作者、venue 和版本；
2. 从论文关键词、方法名、数据集和参考文献生成查询；
3. 追踪 2–3 篇被引用的关键工作和 2–3 篇后续引用；
4. 判断该论文是经典工作、可复现 baseline，还是只适合建立背景。

### 只有宽泛方向

1. 把方向改写成“对象 + 任务 + 约束 / 失败现象”；
2. 找一篇近年的综述、教程或代表性论文作为种子；
3. 从种子抽取术语，再使用引文追踪和 venue 扫描补齐方法家族；
4. 发现关键词仍持续变化时，不要急着下载完整代码和数据。

### 想尽快完成第一次复现

1. 先找近年、开源、框架较清楚且资源可承受的候选；
2. 核验官方仓库、训练 / 评测命令、数据、许可证和近期 issue；
3. 先运行预训练评测或最小 demo，再决定是否投入完整训练；
4. “开源”只说明存在公开入口，不等于环境可重建、结果可复现或适合作为首篇 baseline。

## 30–45 分钟首轮流程

### 1. 冻结任务句（3 分钟）

使用下面的句式：

```text
我要了解 [对象 / 场景] 中的 [任务]，重点比较 [方法或约束]，
暂不覆盖 [相邻问题]，目的是选择 [阅读 / baseline / 数据 / 评价]。
```

没有任务句时，平台推荐和关键词扩展很容易无限增长。

### 2. 选择一个发现入口（5–10 分钟）

| 当前需要 | 建议入口与边界 |
| --- | --- |
| 宽泛检索与引文追踪 | [Google Scholar](https://scholar.google.com/)；可查看相关论文、引用和其他版本，但覆盖和更新并非完整性保证。 |
| 计算机 venue / 作者书目 | [DBLP](https://dblp.org/)；适合确认书目和电子版入口，不替代全文与实验结论。 |
| arXiv 新论文与主题跟踪 | [arXiv](https://arxiv.org/)或主题聚合入口；聚合页负责发现，版本与正文回到 arXiv。 |
| 顶会或细分方向浏览 | CV Paper Portal、Paper Copilot、Cool Papers、CosmosPaper 等；先核对其实际 venue 和年份范围。 |
| 公开投稿与评审上下文 | [OpenReview](https://openreview.net/)；只适用于使用该平台且公开相应信息的 venue。 |

趋势页、获奖论文列表和主题门户适合生成种子，不构成质量排名，也不能证明某方向已经查全。

### 3. 建立种子与关键词组（5 分钟）

从一到三篇种子论文中分别抽取：

- 问题对象：场景、输入、输出、目标用户；
- 方法机制：模型家族、关键模块、训练或推理策略；
- 数据评价：数据集、任务、指标和协议；
- 约束失败：资源、鲁棒性、偏差、长尾、域迁移或失败现象；
- 排除词：同名但不同任务的术语。

把每次组合保存为完整查询式。查询过宽时增加对象或机制，过窄时删除实现细节或换同义词；不要只改页面筛选而不留记录。

### 4. 走一次正反向引用（5–10 分钟）

- **向后追踪**：从种子参考文献找到问题定义、经典方法和评价来源；
- **向前追踪**：从 `Cited by`、相关工作或后续 venue 找修正、反例和新方法；
- **作者 / 项目追踪**：核对作者主页、项目页或仓库，判断是否有扩展版、数据或实现。

引用次数只能帮助排序，不能替代相关性、证据质量和版本核验。

### 5. 归一化论文身份（5–10 分钟）

对准备纳入的候选逐项回答：

```text
稳定标识是什么？
正式发表、OpenReview 与 arXiv 是否为同一工作？
我实际阅读的是哪个版本、哪一天访问？
标题、作者、附录或实验是否发生变化？
官方代码由谁链接，它对应哪个版本？
```

默认去重顺序：DOI → arXiv ID → 规范化标题 + 第一作者 + 年份 → 人工判断版本关系。预印本、会议版和扩展版不要直接删除，应归到同一主记录并说明差异。

### 6. T0 筛选并停止（5 分钟）

只看标题、摘要、主要图表、结论、元数据和资源页，将论文分为：

- **纳入**：直接影响当前问题或 baseline 选择；
- **保留**：可能用于背景、数据、评价或反例；
- **排除**：任务、对象、证据或资源明显不匹配；
- **待核验**：版本、录用、代码或元数据冲突。

满足以下条件即可结束首轮：已有 2–3 篇可定向阅读的核心候选；主要方法、数据和评价术语能够写出；新增结果开始重复；未覆盖范围和下一轮触发条件已记录。

## 平台使用边界

### 聚合入口

- 页面显示的论文数只代表该平台在当时条件下的可见记录；
- 手工收录、第三方同步和主题筛选都可能造成遗漏或重复；
- AI 摘要、标签、BibTeX 和“代码链接”必须回原文、DOI、venue 或仓库核验；
- 平台的年份与 venue 范围要写入查询记录，不能外推为整个 AI / CS 领域。

### 版本与引用

- arXiv 的每个版本永久保留，标题、作者和正文可能随版本变化；需要精确复现时记录完整版本号；
- Google Scholar 的“所有版本”可帮助发现副本，但最终引用仍应核对正式出版页或实际使用的原文；
- DBLP 提供计算机科学书目元数据和电子版链接，不证明论文中的实验结论；
- OpenReview 的投稿、评审和决定应按 venue 的公开范围理解，不把公开页面外推为完整评审事实。

## AI 可以做什么

可以让 AI：

- 根据任务句提出关键词组合和排除词；
- 把导出的元数据规范化为统一字段；
- 标出标题、作者、年份或版本冲突，生成待核验清单；
- 对已提供的摘要或原文做结构化提取。

不应让 AI：

- 在没有可访问链接的情况下补论文、DOI、作者或代码；
- 根据标题或聚合摘要判断结论成立；
- 自动选择“权威版本”并覆盖人工记录；
- 把检索结果数、热度或引用数解释成研究质量。

## PASS / STAY / STOP

| 决定 | 条件与下一步 |
| --- | --- |
| **PASS** | 候选有稳定标识、原文版本和筛选理由；核心论文进入阅读卡，baseline 候选进入准入卡。 |
| **STAY** | 关键词仍大幅变化、版本冲突未解决或没有可执行候选；缩小任务并再做一轮查询。 |
| **STOP** | 当前入口与任务不匹配、关键资源不可得或预算超限；保留记录并切换候选，不继续堆 PDF。 |

使用[文献检索账本与领域地图](../templates/07-literature-search-log.md)保存上述证据。若要声称系统综述、查全率或正式证据综合，需要采用对应领域的数据库、检索式、双人筛选和报告规范；本指南只服务于零基础阶段的代表性文献集合。

## 依据与进一步阅读

- [Google Scholar Search Help](https://scholar.google.com/intl/us/scholar/help.html)：相关性 / 日期排序、引用追踪、相关论文、版本和覆盖边界；
- [Google Scholar Inclusion Guidelines for Webmasters](https://scholar.google.com/intl/en/scholar/inclusion.html)：可索引内容与元数据要求；
- [DBLP FAQ：数据记录内容](https://dblp.org/faq/1474565)：书目元数据与电子版链接的职责；
- [arXiv 版本说明](https://info.arxiv.org/help/versions.html)：版本永久性、替换、撤回和版本化引用；
- [Zotero 重复项说明](https://www.zotero.org/support/duplicate_detection)：重复候选与合并记录；
- [Hermes Agent research-paper-writing workflow](https://github.com/nousresearch/hermes-agent/blob/main/skills/research/research-paper-writing/SKILL.md)：种子论文、结构化搜索和引用核验思路；
- [ASReview](https://github.com/asreview/asreview)：规模扩大后的结构化筛选参考，不作为首轮小集合的前置工具。
