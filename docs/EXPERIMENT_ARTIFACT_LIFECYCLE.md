# 实验产物保留、归档与安全清理

这份指南用于决定实验结束后哪些内容继续保留、归档、只留记录或按政策删除。目标不是“所有文件永久保存”，也不是“磁盘满了就删旧 checkpoint”，而是让每项研究主张和关键决定在需要时仍能被解释、复查或依法处置。

## 什么时候启用

- 运行开始产生大量 checkpoint、预测、缓存或日志；
- 本地磁盘、云存储或 tracker 配额接近上限；
- 关键实验完成、项目暂停、交接、投稿或结题；
- 平台产物设置了 TTL，或服务器 / 账号即将回收；
- 数据使用权、撤回请求、匿名要求或机构政策要求删除。

不要等到存储告警或毕业前才第一次盘点。开始正式实验时先声明分类、负责人和复查日期，项目结束时再做最终归档决定。

## 先按用途分类，不按“结果好坏”分类

| 类别 | 典型内容 | 默认处理 |
| --- | --- | --- |
| `T0_TRANSIENT` | 下载缓存、可重建中间文件、临时可视化、重复副本 | 验证可重建且无引用后可清理；不作为唯一证据 |
| `R1_RECOVERY` | 最近恢复 checkpoint、优化器状态、未完成运行日志 | 保留到运行完成、恢复测试通过并产生下一稳定恢复点 |
| `E2_EVIDENCE` | 全部 trial 的元数据、失败原因、冻结配置、逐样本预测、指标输入、关键日志、支撑决定的 checkpoint | 只要结论、图表、交接或评审仍依赖就保留；大二进制可在满足清理门后只留可重建记录 |
| `A3_ARCHIVE` | 与论文 / 报告对应的代码快照、环境、数据 manifest、评价脚本、图表源数据、最终模型和 README | 按机构、资助方、venue 与仓库政策长期归档；需要时使用有持久标识和保留政策的仓库 |
| `S_RESTRICTED` | 个人信息、受限数据、私有代码、匿名审稿材料、合同资产 | 由伦理、同意、合同和机构政策优先决定访问与删除；不得因归档而扩大共享 |

失败、剪枝、阴性结果或未采用配置不是 `T0_TRANSIENT` 的同义词。至少保留其 run ID、状态、配置身份、失败阶段、首个关键错误、排除或停止理由，以及它如何影响后续决定。是否保留大体积权重由证据依赖和可重建性决定。

## 从主张反向建立保留清单

对每项准备进入组会、报告或论文的结论反向检查：

```text
主张 / 决定
  → 图表或汇总表
  → 指标输入与评价脚本
  → 全部纳入、排除和失败 run IDs
  → 配置、代码、环境和数据 revision
  → 必须保留的原始或受限来源
```

任何仍被这条链引用的唯一资产都不能仅因“不是最佳模型”而删除。若某个二进制可由已归档代码、数据和配置合理重建，先记录成本、容差和验证结果，再考虑只保留 manifest、哈希与重建入口。

## 最小生命周期台账

在现有实验索引、tracker 或 `artifacts/README.md` 增加以下字段即可，不要求新建第二套表：

| 资产或集合 | run / claim 引用 | 分类 | 唯一位置与身份 | 大小 | 负责人 | 复查日 / 到期 | 决定与证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  | T0 / R1 / E2 / A3 / S | path / URI / hash |  |  |  |  |

“保留 90 天”不能只写数字，还要写从哪一天起算、到期后由谁复查、平台是否自动删除，以及删除后保留什么记录。

## 清理前必须通过的门

1. **身份**：列出精确路径、URI、run ID、哈希或 artifact version，不使用模糊通配描述目标；
2. **引用**：检查论文图表、交接卡、模型注册表、Git / DVC 历史和下游任务是否仍引用；
3. **唯一性**：确认它不是唯一原始数据、唯一恢复点、唯一评价输入或唯一失败证据；
4. **可重建性**：对声明可重建的资产实际完成一次小规模恢复或重算，而不是只看到脚本存在；
5. **权限**：受限资产按负责人、伦理、合同、机构和资助方政策批准，不能由个人习惯决定；
6. **备份**：关键归档至少有一个与工作副本独立的备份，并完成恢复抽查；同步盘不是误删保护的充分证明；
7. **墓碑记录**：清理后仍保留资产身份、分类、原因、批准人、时间、影响和替代入口；
8. **人工确认**：任何远端垃圾回收、批量删除和策略变更先查看候选清单，不允许 AI 自动批准。

本仓库不提供一键删除命令。不同平台的引用语义和权限差异很大，清理必须在目标清单、影响范围和恢复证据确认后使用对应官方流程。

## 只作一个生命周期决定

| 状态 | 含义与下一步 |
| --- | --- |
| `KEEP_ACTIVE` | 当前运行、恢复或分析仍依赖，保持活动存储。 |
| `ARCHIVE_IMMUTABLE` | 进入提交、发布或长期复查链，冻结身份并保存恢复说明。 |
| `PRUNE_BINARY_KEEP_RECORD` | 大二进制已确认可重建且无唯一证据依赖；删除后保留元数据、哈希、原因和重建入口。 |
| `HOLD_RESTRICTED` | 访问或删除由外部政策决定；停止个人清理并交给负责人。 |
| `REVIEW_REQUIRED` | 引用、唯一性、权限或恢复能力不清，不执行删除。 |

涉及法定删除或受试者撤回时，执行机构批准的处置并保留允许保存的审计信息；不要把 `ARCHIVE_IMMUTABLE` 理解成可以违反删除义务。

## 常见平台的到期与删除陷阱

- **GitHub Actions**：workflow artifact 与日志存在可配置保留期，默认值和上限受仓库类型及组织策略影响；CI 链接不能作为长期论文归档位置；
- **Weights & Biases**：artifact 可以设置 TTL，但修改权限可能由团队管理员控制；需要把关键版本排除在临时 TTL 策略之外并验证实际状态；
- **MLflow**：删除 run 可以先进入 deleted 生命周期，但 `mlflow gc` 会永久删除元数据和 artifact，且不会因 UI pin 或标签自动保护；
- **DVC**：垃圾回收会按所选 Git / workspace 引用范围删除缓存或远端对象；未推送、未被正确引用或共享缓存中的数据可能永久丢失；
- **本地服务器与同步盘**：账号到期、scratch 自动清理、覆盖同步和个人设备损坏都可能使“路径仍在文档中”失去意义。

平台规则会变化，执行前核验当前官方文档、团队策略和管理员权限。

## 项目结束时的最小归档包

- 项目入口、研究问题、最终决定、限制和负责人；
- 代码 commit / release、依赖锁定、配置与最小运行说明；
- 数据来源、revision、split、manifest、校验值、权利与访问边界；
- 全部关键 run IDs、状态、失败 / 排除理由和评价协议；
- 支撑图表与主张的指标输入、脚本、图表源文件和对应关系；
- 保留资产、已清理资产的墓碑记录、恢复测试和下一复查时间；
- 实际提交版本、评审、回复、决定和可公开发布入口。

## 最低验收清单

- [ ] 临时、恢复、证据、归档和受限资产已经区分；
- [ ] 失败 / 剪枝 / 阴性运行至少保留可解释元数据和决定理由；
- [ ] 关键主张可以反向定位到仍存在的评价输入和运行身份；
- [ ] 每项大资产有负责人、大小、位置、复查日与状态；
- [ ] 平台 TTL、账号到期和自动清理规则已经核验；
- [ ] 清理候选完成引用、唯一性、权限、恢复和备份检查；
- [ ] 清理后保留墓碑记录，没有让交接或论文链接变成空入口；
- [ ] 受限资产遵循更高优先级政策，没有被误公开或擅自长期保留。

## 依据与延伸阅读

- [The Turing Way：Data Management Plan](https://book.the-turing-way.org/reproducible-research/rdm/rdm-dmp/)：在项目内持续更新生成、存储、访问、共享、项目后保存与成本计划；
- [The Turing Way：Data Storage and Organisation](https://book.the-turing-way.org/reproducible-research/rdm/rdm-storage.html)：按价值和变化频率设计备份，并遵循机构规则；
- [GitHub Actions artifact 与日志保留期](https://docs.github.com/en/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization)：平台产物会按设置自动到期；
- [W&B artifact TTL](https://docs.wandb.ai/models/artifacts/ttl)：为 artifact version 设置保留策略及其管理员权限边界；
- [MLflow CLI `gc`](https://mlflow.org/docs/latest/api_reference/cli.html)：永久清理 deleted run 的元数据与 artifact，且不会检查 UI pin；
- [DVC garbage collection](https://dvc.org/doc/command-reference/gc)：按 workspace、分支、标签或提交引用范围清理缓存与远端对象；
- [NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)：报告实验设置、计算资源、评价和可复现信息时应能回到对应证据。
