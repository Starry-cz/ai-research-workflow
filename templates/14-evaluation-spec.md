# 评价协议卡

在查看最终测试结果前填写并冻结。一个主要实验对应一个主指标和一个主要决策。

## 1. 主张与决策

- 项目 / 实验 ID：
- 要检验的主要主张：
- 本轮要做的决策：
- 评价对象与真实泛化目标：
- 主要错误类型及代价：
- baseline 与比较对象：
- 冻结日期、负责人和版本：

## 2. 数据与权限

- 数据集卡：
- 数据 revision 与 split manifest：
- 评价样本范围：
- 独立统计单位：样本 / group / 用户 / 文档 / 查询 / 任务 / 运行 / 其他
- 验证集允许的选择：
- 测试集首次可见条件：
- 已知污染、依赖和覆盖边界：

## 3. 主指标

- 名称与一句话含义：
- 越高越好 / 越低越好 / 目标区间：
- 公式或可靠定义链接：
- 代码包、版本、函数与 commit：
- 完整参数：
- 正类、标签顺序或匹配定义：
- macro / micro / weighted / per-group / 其他聚合：
- 阈值、`K`、候选集合或容差：
- 空集合、无预测、NaN、超时和失败样本处理：
- 手算或已知样例及预期值：
- 从保存预测重算的命令：

## 4. 选择与辅助指标

- 训练 loss 及用途：
- 验证集选择指标：
- checkpoint / 阈值 / 超参数选择规则：
- 调参协议 / study ID：
- baseline 与候选各自的搜索空间、trial 上限和资源预算：
- 搜索算法、随机状态、早停 / 剪枝和失败处理：
- 已完成、失败、剪枝和人工调整的统一记录位置：
- 最终配置冻结条件与配置 / commit：
- 辅助质量指标及各自回答的问题：
- 分 group / 类别 / 场景报告：
- 效率、成本和安全指标：
- 为什么这些指标不替代主指标：

## 5. 重复运行与不确定性

- 主要变异来源：初始化 / 数据抽样 / split / 人工评价者 / 系统 / 其他
- 预先计划的运行、seed、fold 或重采样：
- 配对比较单位：
- 中心趋势：
- 离散、区间或检验方法：
- 统计方法的假设与不适用条件：
- 实际意义、非劣或停止门槛：
- 多重比较处理（如适用）：
- 资源不足时如何收缩主张：

## 6. 人工评价或模型评审（如适用）

- 评价构念与 rubric 路径：
- 完整说明、示例和校准：
- 样本数量、抽样与顺序随机化：
- 是否盲法：
- 评价者人数、背景、招募、报酬、同意与伦理审批：
- 每样本评价人数与分歧处理：
- 一致性或可靠性报告：
- 无效、缺失与退出处理：
- 模型评审的模型 / 版本 / prompt / 参数 / 解析 / 重试：
- 人工校准样本与已知偏差：

## 7. 冻结、变更与决策

- 评价脚本、commit 与环境：
- 逐样本预测输出路径和 schema：
- 协议冻结后的禁止改动：
- 测试结果可见后修改配置、指标或数据的证据降级规则：
- 新一轮调参是否需要新的独立测试证据：
- 实现错误的修订与旧结果作废规则：
- `PROCEED / REFINE / PIVOT / STOP` 门槛：
- 主指标支持什么结论：
- 主指标不能支持什么结论：
- 审核人和审核时间：

> 不要在看到测试结果后静默更换指标、aggregation、阈值、seed、子集或排除规则。`±` 必须说明是什么、对什么单位计算、用了多少次观察。
